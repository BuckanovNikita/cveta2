# Managed contracts

## Configuration
Shared file: schema_version: 1; cvat: {host, organization}; projects: {key: {id, name?, sync_root?, ignored_prefix?, task_cache_s3?, ignore: []}}; datasets: {key: {sources: [{name, type: cvat, project: key} | {name, type: s3-csv, uri: s3://bucket/file.csv}], clearml: {project, dataset}, api_url, s3_roots: [], empty_classes: [], splits: {train: 0.6, val: 0.2, test: 0.2, seed: 42}, overlaps: {sha256: {source: source-name | null, members: [source-name]}}}}. Unknown keys rejected; no secrets or local paths in shared policy. Source names are unique per dataset; destination pairs unique globally. Personal settings retain existing auth/network/upload/local-path fields and add schema_version/project_config. The existing personal cvat host/org become legacy-only and migrate to shared cvat. Unconfigured standalone mode remains usable until a legacy file needs reviewed migration.

## Provenance and source snapshots
Reserved CSV fields source_id, source_project_id, source_task_id, source_frame_id, source_row_id. Never invent CVAT identity for S3 rows. Fetch exports sources/<source-name>/{dataset,obsolete,in_progress,deleted}.csv, source-snapshot.yaml and combined dataset.csv in a fresh directory. Source names are safe identifiers. Completed per-task snapshots retain rows lost to project-level partitioning. All snapshots are typed JSON-compatible YAML values; raw source tables preserve lexical cells.

## Pure policies
assign_splits(frame, policy, image_hashes, previous) -> (frame, assignments). image_hashes maps image_path to sha256. resolve_overlaps(frame, image_hashes, decisions) -> frame; digest decisions are bound to exact source membership. compare_frames(old,new) -> JSON-compatible change summary. Policies perform no file/network IO. Source merge filters within source before global training validation. Stable hash maps new content to target ratios; train/val viability is checked rather than silently rebalanced.

## Commands
cveta2 setup --project-config PATH attaches without connection prompts. setup --migrate-config previews, then asks to activate. dataset list/show NAME/versions NAME/fetch NAME/prepare NAME CSV/diff OLD NEW/report-errors PREPARED/publish PREPARED. fetch requires --output-dir; prepare requires --source fetch-directory and --output-dir; prepare --clean accepts cleanup. Managed commands accept --config and --project-config, never mapping overrides. publish/report-errors operate on immutable local preparation and re-resolve bound policy. Inspect/diff commands support --json. Missing user decisions are errors for APIs/noninteractive mode. CSV and other failures map to existing exit code conventions.

## Publication
Legacy dataset.yaml/tasks.yaml remain readable. Optional managed extensions are versioned typed fields; format_version=2 applies to local preparation only. Payload inventory remains dataset.csv,dataset.yaml,tasks.yaml. At publish, recheck exact parent, relevant definition, registry, live task facts, S3 hash and media; own issue-only changes must not invalidate original annotation freshness. Ambiguous provenance remains unmapped, never written to CVAT. Feedback failures block publication and retain a resumable ledger. No annotations/status edits. A legacy parent requires full refresh, not fabricated source data.
