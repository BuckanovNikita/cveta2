# Verification concepts

No product model or serialized dataset changes.

A verification run has commands, inputs, exit outcomes and dated observational
evidence. Evidence is not a persistent success cache. A worktree owns its mutable
tool state. A testmon environment namespace identifies inputs outside its Python
content tracking. A release attempt reuses successful live acceptance only on its
unchanged clean branch tip. Deferred verification is required work blocked by
unavailable infrastructure and cannot transition to accepted without execution.
