# Кэш изображений и аннотаций

cveta2 хранит на диске три вида данных: изображения проектов, сохранённые аннотации CVAT и состояние незавершённых загрузок. На этой странице описано, где они лежат, кто их пишет и читает и как их обновить.

## Кэш изображений

Кэш изображений ([image cache](../GLOSSARY.md)) — локальный каталог, куда cveta2 скачивает изображения проекта из S3.

### Как выбирается каталог проекта

Для проекта с именем `Retail shelves` каталог определяется так (первое найденное значение):

1. Ключ `image_cache.Retail shelves` личной конфигурации ([personal configuration](../GLOSSARY.md)).
2. `<images_root>/Retail shelves`, где `images_root` берётся из `cache.projects.Retail shelves.images_root`, а если его нет — из `cache.images_root`.
3. Ничего: каталог не задан.

В имени проекта символы `/`, `\` и `%` кодируются как `%2F`, `%5C` и `%25`, поэтому каталог всегда лежит внутри корня.

У `cveta2 fetch` флаг `--images-dir` заменяет каталог на один запуск, а `--no-images` отключает скачивание. Если каталог не задан, `fetch` в терминале спрашивает путь и сохраняет его в `image_cache`; при `CVETA2_NO_INTERACTIVE=true` он завершается ошибкой. Настроить пути удобно командой [`cveta2 setup-cache`](commands/setup-cache.md). Ключи описаны в [Конфигурация](configuration.md).

### Как ключи S3 превращаются в локальные пути

Изображения берутся из облачного хранилища (cloud storage) CVAT, привязанного к проекту: бакет, префикс и адрес сервера cveta2 читает из CVAT. Корень синхронизации ([sync root](../GLOSSARY.md)) из общей конфигурации ([shared configuration](../GLOSSARY.md), ключ `projects.<ключ>.sync_root`) или флаг `--root` команды `s3-sync` заменяет этот бакет и префикс.

Локальный путь — это ключ S3 без начальной части:

- по умолчанию отбрасывается префикс хранилища (или корня синхронизации);
- если в общей конфигурации для проекта задан отбрасываемый префикс ([ignored prefix](../GLOSSARY.md), `projects.<ключ>.ignored_prefix`), отбрасывается только он.

Подкаталоги после отброшенной части сохраняются. Пример для хранилища `s3://my-bucket/images`:

| Ключ S3 | `ignored_prefix` | Локальный путь |
|---|---|---|
| `images/2026-02/a.jpg` | не задан | `<каталог проекта>/2026-02/a.jpg` |
| `images/2026-02/a.jpg` | `images/2026-02` | `<каталог проекта>/a.jpg` |

Ключ, который не начинается с отбрасываемой части, сохраняется целиком. Пути с `..`, пустыми частями или выходящие за каталог проекта отклоняются с ошибкой `Небезопасный путь изображения ...`.

### Права на файлы

Новые каталоги получают права `rwxrwxr-x` (775), новые файлы — `rw-rw-r--` (664), чтобы кэш могли делить несколько пользователей одной группы. Права уже существующих каталогов не меняются. Файл сначала пишется во временный файл рядом и потом переименовывается, поэтому оборванная загрузка не оставляет обрезанного изображения.

### Кто заполняет и кто читает

| Команда | Что делает с кэшем |
|---|---|
| [`fetch`](commands/fetch.md), [`fetch-task`](commands/fetch-task.md) | Скачивают изображения из строк выгрузки, которых ещё нет на диске, и пишут путь к файлу в колонку `image_path`. |
| [`s3-sync`](commands/s3-sync.md) | Скачивает все объекты под префиксом хранилища, которых нет на диске. Локальные файлы не удаляет, в S3 ничего не пишет. |
| [`upload`](commands/upload.md) | Ищет изображения в `--image-dir`, затем в каталоге проекта. |
| [`convert`](commands/convert.md) | Ищет изображения по имени в `--image-dir`, затем во всех каталогах секции `image_cache`. |
| [`verify`](commands/verify.md) | С `--check-images` открывает файлы из колонки `image_path`; для пустых ячеек — из `--image-root`. |

Файл, который уже есть на диске, считается готовым и повторно не скачивается. Чтобы перекачать изображение, удалите файл.

`s3-sync` без `--project` обходит только проекты, названные в секции `image_cache` или `cache.projects` личной конфигурации, и проекты, для которых общая конфигурация задаёт `ignored_prefix` или `task_cache_s3`. Проект, для которого задан только общий `cache.images_root`, синхронизируйте с `--project`.

`convert` не смотрит в `cache.images_root` и в колонку `image_path`: если путь проекта не записан в `image_cache`, передайте каталог через `--image-dir`.

`s3-sync` не пропускает служебные объекты: если кэш аннотаций в S3 лежит в месте по умолчанию (`<префикс хранилища>/.cveta2_cache/...`, см. ниже), эти файлы тоже скачиваются в каталог изображений, в подкаталог `.cveta2_cache/`.

### Доступ к S3

cveta2 создаёт клиент S3 со стандартной цепочкой учётных данных boto3: переменные окружения `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` или файлы `~/.aws`. Адрес сервера S3 берётся из облачного хранилища CVAT. Таймауты и число параллельных потоков описаны в [Конфигурация](configuration.md).

## Кэш аннотаций

Кэш аннотаций ([annotation cache](../GLOSSARY.md)) хранит то, что `fetch` и `fetch-task` прочитали из CVAT, чтобы не запрашивать это снова.

### Что сохраняется

- Фигуры (shapes) каждого job — файл `job_<ID>.json`. Если jobs задачи нельзя разделить (Ground Truth, consensus, пересекающиеся диапазоны кадров), фигуры всей задачи хранятся одной записью.
- Метаданные кадров и issues задачи — файл `meta.json`.

Запись сохраняется, только когда каждый job, который она покрывает, находится в stage `acceptance` со state `completed`. Для `meta.json` это условие действует для всех jobs задачи. Jobs в работе каждый раз читаются из CVAT.

### Когда запись используется

Запись используется, пока совпадают:

- время обновления задачи;
- состав jobs, их stage, state, диапазоны кадров и время обновления;
- версия формата записи.

Иначе данные читаются из CVAT заново и запись перезаписывается; устаревшая локальная запись удаляется сразу. Изменение меток (label) проекта меняет время обновления каждой задачи, поэтому сбрасывает весь кэш проекта.

В конце `fetch` печатает, сколько задач взято из кэша:

```text
Обработка задач: ...; из кэша: 5, загружено с CVAT: 2, ...
```

### Где хранится

Локально: `<tasks_root>/project_<ID проекта>/task_<ID задачи>/`. Без `cache.tasks_root` это `~/.cache/cveta2/task_annotations/` (или `$XDG_CACHE_HOME/cveta2/task_annotations/`).

В S3 (общий для всех пользователей). Место задаёт ключ `projects.<ключ>.task_cache_s3` общей конфигурации. Без него и без облачного хранилища у проекта кэш хранится только локально:

| Настройка | Ключи записей |
|---|---|
| по умолчанию | `<префикс хранилища>/.cveta2_cache/task_annotations/task_<ID>/...` в бакете проекта |
| `task_cache_s3: s3://my-bucket/cveta2-cache` | `cveta2-cache/task_annotations/task_<ID>/...` в бакете `my-bucket` |
| `task_cache_s3: cveta2-cache` | `cveta2-cache/task_annotations/task_<ID>/...` в бакете проекта |

S3-кэш строится по хранилищу CVAT, корень синхронизации на него не влияет. Порядок чтения: локальная запись, затем S3; запись из S3 копируется в локальный кэш. Новая запись пишется в оба места. Если S3 отвечает ошибкой (кроме «объекта нет»), до конца запуска используется только локальный кэш:

```text
S3-кэш аннотаций недоступен (<ошибка>) — до конца запуска используется только локальный кэш.
```

### Как обойти или обновить

| Способ | Действие |
|---|---|
| `fetch --force`, `fetch-task --force` | Не читать кэш, загрузить всё из CVAT и перезаписать записи. |
| `fetch --no-cache`, `fetch-task --no-cache` | Не читать и не писать кэш. |
| `CVETA2_DISABLE_CACHE=true` | То же, что `--no-cache`, для всех команд. Записи, которые удаляют команды ниже, удаляются только локально. |
| удалить каталог `task_annotations/project_<ID>` | Локальные записи исчезнут; при следующем `fetch` они вернутся из S3, если там есть. |

### Кто очищает

- `fetch` (полная выгрузка, [full fetch](../GLOSSARY.md)) удаляет локальные записи задач, которых больше нет в проекте. `fetch-task` этого не делает.
- `fetch --skip-validation` удаляет записи задачи (локально и в S3) перед тем, как принять её jobs.
- [`upload`](commands/upload.md) удаляет записи созданной задачи.
- Подкоманды [`task`](commands/task.md) удаляют записи изменённой задачи локально и в S3.

## Состояние загрузки

`cveta2 upload` сохраняет манифест загрузки ([upload manifest](../GLOSSARY.md)) в

```text
~/.cache/cveta2/uploads/<хэш адреса CVAT>/project_<ID проекта>/<отпечаток>.json
```

(или в `$XDG_CACHE_HOME/cveta2/uploads/...`). Отпечаток считается по датасету, меткам, имени задачи и параметрам загрузки. Манифест позволяет `upload --resume` с теми же `--dataset` и `--labels` продолжить прерванную загрузку и не создать вторую задачу. После успешного завершения манифест удаляется. Подробнее — в [cveta2 upload](commands/upload.md).

## Расположение на диске

Пример после `cveta2 fetch` и `cveta2 s3-sync` с `cache.images_root: ~/data/images` и настройками кэша по умолчанию:

```text
~/data/images/
└── Retail shelves/               каталог проекта (кэш изображений)
    ├── 2026-02/
    │   └── shelf_0009.jpg
    └── shelf_0025.jpg

~/.cache/cveta2/                  или $XDG_CACHE_HOME/cveta2/
├── task_annotations/
│   └── project_123/
│       ├── task_456/
│       │   ├── job_789.json
│       │   └── meta.json
│       └── task_457/
├── uploads/
│   └── <хэш адреса CVAT>/
│       └── project_123/
│           └── <отпечаток>.json
└── prompt_history/               история ответов на вопросы в терминале

~/.config/cveta2/
├── config.yaml                   личная конфигурация
└── projects.yaml                 список проектов CVAT
```

В бакете хранилища проекта:

```text
s3://my-bucket/images/
├── 2026-02/shelf_0009.jpg
└── .cveta2_cache/
    └── task_annotations/
        └── task_456/
            ├── job_789.json
            └── meta.json
```
