# Конфигурация

## Файл конфигурации

По умолчанию используется `~/.config/cveta2/config.yaml`. Создать его проще всего через `cveta2 setup` (креды) и `cveta2 setup-cache` (пути к изображениям).

Минимальный пример:

```yaml
cvat:
  host: "https://app.cvat.ai"
  organization: "my-team"
  username: "your-username"
  password: "your-password"
```

Полный пример конфига со всеми секциями:

```yaml
cvat:
  host: "https://app.cvat.ai"
  organization: "my-team"
  username: "your-username"
  password: "your-password"
  request_timeout: 300  # таймаут чтения HTTP-запросов в секундах; не задан или 0 — без таймаута

image_cache:
  coco8-dev: /mnt/disk01/data/project_coco_8_dev
  my-other-project: /home/user/datasets/other

sync_roots:
  coco8-dev: s3://other-bucket/mirrors/coco8   # или просто "some/prefix" в бакете проекта
  my-other-project: some/other/prefix

cache:
  images_root: /home/user/datasets             # корень кэша изображений для проектов без записи в image_cache
  tasks_root: /mnt/disk01/task-cache           # локальный корень кэша аннотаций задач
  projects:
    coco8-dev:
      images_root: /mnt/disk02/coco8           # переопределяет cache.images_root для этого проекта
      tasks_root: /mnt/disk02/coco8-tasks      # переопределяет cache.tasks_root для этого проекта
      ignored_prefix: data                     # часть S3-ключа, отбрасываемая при локальном сохранении
      task_cache_s3: s3://ml-cache/coco8-dev   # явное место S3-кэша задач (или голый префикс в бакете проекта)

upload:
  images_per_job: 100                          # изображений на job в создаваемой задаче
  image_quality: 100                           # качество изображений в CVAT

network:
  s3_workers: 16                               # параллельных передач файлов на S3
  cvat_workers: 4                              # параллельных запросов к CVAT
  retry_attempts: 5                            # всего попыток на запрос, включая первую
  retry_max_wait: 30                           # максимальная пауза между попытками, секунды

clearml:
  enabled: true                                # публикация CSV в ClearML после полного fetch
  projects:
    coco8-dev:
      clearml_project: "CV/coco8"
      clearml_dataset: "coco8-dev"

ignore:
  coco8-dev:
    - id: 456
      name: "Партия 3"
      description: "Дубликаты"
      silent: true                             # не предупреждать об этой задаче при fetch
```

Поле `cvat.request_timeout` (или переменная `CVETA2_DATA_TIMEOUT`, у неё приоритет) включает таймауты для всех HTTP-запросов к CVAT (включая создание клиента) и операций с S3: таймаут соединения — 10 секунд, таймаут чтения — заданное значение. По умолчанию (не задано или `0`) таймаутов нет — запрос может ждать сколько угодно.

## Пресет по умолчанию

cveta2 содержит встроенный пресет (`cveta2/presets/default.yaml`), который задаёт `host: http://localhost:8080`. Если вы работаете с локальным CVAT — достаточно добавить только креды.

## Приоритет источников

1. **Переменные окружения** — переопределяют файл и пресет
1. **Файл конфигурации** (`~/.config/cveta2/config.yaml`)
1. **Встроенный пресет** — базовые значения по умолчанию
1. **Интерактивный ввод** — если не указаны логин/пароль

## Переменные окружения

| Переменная | Описание |
|---|---|
| `CVAT_HOST` | URL сервера CVAT |
| `CVAT_ORGANIZATION` | Slug организации CVAT |
| `CVAT_USERNAME` | Имя пользователя |
| `CVAT_PASSWORD` | Пароль |
| `CVETA2_CONFIG` | Путь к файлу конфигурации (по умолчанию `~/.config/cveta2/config.yaml`) |
| `CVETA2_NO_INTERACTIVE` | Установите `true`, чтобы отключить все интерактивные промпты (см. ниже) |
| `CVETA2_DATA_TIMEOUT` | Таймаут чтения (в секундах) для всех HTTP-запросов к CVAT и операций с S3; таймаут соединения — 10 секунд. Не задан или `0` — без таймаутов (поведение по умолчанию). Переопределяет `cvat.request_timeout` из конфига |
| `CVETA2_DISABLE_CACHE` | При `true` — полностью отключить кэш аннотаций задач: ни чтения, ни записи, ни синхронизации с S3. Эквивалент постоянного `--no-cache` (см. [Кэш аннотаций задач](images-and-cache.md#кэш-аннотаций-задач)) |
| `CVETA2_RAISE_ON_FAILURE` | При `true` — при первой ошибке CVAT 5xx по задаче вызов `fetch`/`fetch-task` сразу падает (исключение пробрасывается). По умолчанию такие задачи пропускаются, ошибка и ссылка на задачу пишутся в лог |
| `CVETA2_CLEARML` | При `false` — отключить публикацию в ClearML на этот запуск (см. [Публикация в ClearML](images-and-cache.md#публикация-в-clearml)) |
| `CVETA2_S3_WORKERS` | Число параллельных передач файлов на S3 на этот запуск; переопределяет `network.s3_workers` |
| `CVETA2_CVAT_WORKERS` | Число параллельных запросов к CVAT на этот запуск; переопределяет `network.cvat_workers` |
| `CVETA2_RETRY_ATTEMPTS` | Общее число попыток на один сетевой запрос (включая первую); переопределяет `network.retry_attempts` |

## Ошибки сервера CVAT (5xx)

При выгрузке аннотаций (`fetch`, `fetch-task`) возможны временные ошибки сервера (HTTP 5xx) по отдельным задачам. По умолчанию такая задача **пропускается**: в лог пишется ошибка и ссылка на задачу, остальные задачи обрабатываются дальше. В лог также выводится готовая команда для добавления сломанной задачи в список игнорируемых — при следующем запуске она не будет запрашиваться:

```text
Чтобы пропустить задачу при следующем запуске: cveta2 ignore --project "имя_проекта" --add 123
```

Если нужно, чтобы вызов завершался при первой же 5xx (например, в CI), установите `CVETA2_RAISE_ON_FAILURE=true`.

## Параллельность передач

Файлы на S3 передаются параллельно — до `network.s3_workers` за раз, в обе стороны (загрузка и выгрузка). Задачи при `fetch` выгружаются до `network.cvat_workers` одновременно; issues и jobs при `upload` — тоже. Пул соединений S3 автоматически подстраивается под `s3_workers`.

Листинг больших хранилищ дополнительно разбивается по подпапкам первого уровня (`YYYY-MM/`) и обходится параллельно. Результат при этом побайтово совпадает с последовательным: порядок ключей сохраняется, потому что на него опирается разрешение одинаковых имён файлов.

`cvat_workers` намеренно меньше `s3_workers`: CVAT начинает ограничивать частоту запросов гораздо раньше, чем объектное хранилище, а каждый ответ 429 стоит паузы — то есть съедает тот же параллелизм, ради которого затевался. Если CVAT всё же отвечает 429, уменьшите `cvat_workers`.

## Повторы запросов и ограничение частоты (429)

Сетевые сбои и временные ошибки сервера повторяются автоматически: до `network.retry_attempts` попыток с экспоненциальной паузой (со случайным разбросом, чтобы параллельные воркеры не возвращались на сервер одновременно) и не дольше `network.retry_max_wait` секунд. Если сервер прислал заголовок `Retry-After`, пауза берётся из него.

Что именно повторяется, зависит от типа запроса:

| Запрос | Повторяется при |
|---|---|
| Чтение (список задач, аннотации, метаданные) | 429, 500, 502, 503, 504 и сетевых сбоях |
| Запись (создание задачи, загрузка аннотаций, issues) | только 429 и 503 с заголовком `Retry-After` |

Разница намеренная. Ответ 429 означает, что запрос **отклонён** и на сервере ничего не изменилось, поэтому его безопасно повторить. Обычная 5xx на записи неоднозначна: CVAT мог применить изменение и не успеть об этом сообщить, а повтор загрузки аннотаций **добавит** второй набор bbox поверх первого (CVAT работает в режиме добавления, а не замены). Поэтому такая ошибка прерывает выгрузку, а не повторяется.

Если CVAT ограничивает частоту (429) и попытки исчерпаны, `fetch` **прерывается**, а не пропускает задачу: молча потерянная задача уменьшила бы датасет по причине, не связанной с её содержимым. Уменьшите `network.cvat_workers` и повторите запуск.

Для S3 отдельно повторяются коды `SlowDown`, `RequestTimeout`, `RequestTimeTooSkewed`, `InternalError` и `503`; ошибки доступа (403) и отсутствия объекта (404) не повторяются.

У CVAT SDK есть собственные повторы внутри HTTP-клиента: до трёх попыток на кодах 502/503/504 и **только для GET-подобных запросов** (POST и PATCH исключены его настройками по умолчанию, 429 в его список не входит). Для чтений эти повторы складываются с описанными выше — на 502/503/504 суммарное число попыток может доходить до `retry_attempts × 3`. Это осознанно оставлено как есть: перенастроить пул соединений SDK извне нельзя, а лишние попытки на временной ошибке безвредны. Именно из-за этих ограничений SDK записи вообще не имели повторов до появления политики выше.

## Неинтерактивный режим

Для использования в CI/скриптах установите `CVETA2_NO_INTERACTIVE=true`. В этом режиме:

- Все интерактивные промпты заменяются на ошибки с подсказкой, какой флаг или переменную окружения нужно использовать
- Команды `setup`, `setup-cache` и `setup-clearml` недоступны (у `setup-cache` и `setup-clearml` работает только `--list`) — настраивайте через env-переменные или редактируя файл конфигурации напрямую
- При `fetch` / `fetch-task` без `--project` — ошибка (укажите `-p`)
- При `fetch-task` без `-t` или с `-t` без значения — ошибка (укажите `-t VALUE`)
- Если не хватает учётных данных — ошибка (задайте `CVAT_USERNAME`/`CVAT_PASSWORD`)
- Если путь к изображениям не настроен — ошибка (укажите `--images-dir`, `--no-images` или `image_cache` в конфиге)
- Если выходная директория уже существует — перезаписывается без вопросов
- Команда `upload` требует явных `-p`, `--name` и `--labels` — без любого из них будет ошибка вместо интерактивного вопроса
- Команда `labels` доступна только с `--list` (редактирование меток интерактивно)
- Команда `ignore` без `--add`/`--remove`/`--list` недоступна (интерактивный TUI); `--add`/`--remove`/`--list` работают
- Команды `task drop-label` и `task delete` требуют флаг `--yes` (подтверждение недоступно)

Переменная может быть не установлена вообще — по умолчанию интерактивный режим включён.

```bash
# Пример CI-использования
export CVAT_HOST="https://app.cvat.ai"
export CVAT_USERNAME="ci-bot"
export CVAT_PASSWORD="your-password"
export CVETA2_NO_INTERACTIVE=true

cveta2 fetch -p 123 -o output/ --images-dir /data/images
```
