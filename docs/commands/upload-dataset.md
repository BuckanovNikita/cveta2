# cveta2 upload-dataset

Публикует подготовленный датасет ([prepared bundle](../../GLOSSARY.md)), созданный командой [`verify --bundle`](verify.md#ручная-подготовка---bundle), как новую завершённую версию датасета в ClearML. Перед публикацией ([publication](../../GLOSSARY.md)) команда заново проверяет всё, на чём основана подготовка.

> **Внимание.** Опубликованную версию команда не удаляет и не заменяет. Новая публикация с тем же именем создаёт следующую версию, а не исправляет прежнюю.

## Примеры

Опубликовать подготовленный каталог:

```bash
cveta2 upload-dataset output/prepared-1
```

Полный цикл: подготовить, просмотреть отчёт, опубликовать:

```bash
cveta2 verify ~/data/fetch --bundle --project "Retail/Datasets" --dataset-name retail-shelves \
  --api-url https://classes.example.com/api --local-root ~/data/images \
  --accept-default-classes --clean --output-dir output/prepared-1 --non-interactive
less output/prepared-1/report.json
cveta2 upload-dataset output/prepared-1
```

Если в `dataset.csv` заполнен `s3_image_path`, добавьте к `verify` флаг `--s3-root s3://my-bucket/images`, иначе подготовка остановится с ошибкой `S3 image path is outside approved S3 roots`.

## Синтаксис и аргументы

```text
cveta2 upload-dataset [-h] prepared_dir
```

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `prepared_dir` | обязателен | Каталог, созданный `verify --bundle`, с файлом `preparation.json`. |
| `-h`, `--help` | | Показать справку. |

Проект ClearML, имя датасета, адрес API классов и корни изображений команда берёт из каталога. Изменить их флагами нельзя: для других значений подготовьте датасет заново.

## Как это работает

Для работы нужен настроенный ClearML SDK — так же, как для [`verify --bundle`](verify.md#что-нужно).

1. **Чтение каталога.** Команда читает `preparation.json` и сверяет его хеш SHA-256 с `preparation.sha256`. Затем сверяет хеши четырёх файлов в `sources/` и трёх файлов `dataset.csv`, `dataset.yaml`, `tasks.yaml` с хешами из `preparation.json`. Все файлы должны быть обычными файлами, не символическими ссылками. Три публикуемых файла копируются во временный каталог, и дальше команда работает с этой копией.
2. **Родительский датасет.** Команда заново ищет родительский датасет ([parent dataset](../../GLOSSARY.md)): последнюю завершённую неархивную версию с тем же именем ровно в том же проекте ClearML. Её ID и версия должны совпасть с записанными при подготовке. Если датасета не было и он не появился, это тоже совпадение.
3. **Классы.** Команда заново запрашивает API классов по `api_url` из `dataset.yaml`. Классы должны совпасть с `dataset.yaml` полностью: без новых, переименованных или пропавших классов.
4. **Корни изображений.** Локальные корни из `dataset.yaml` должны существовать и читаться, каждый `image_path` исходного `dataset.csv` должен лежать внутри них, каждый непустой `s3_image_path` — внутри корня S3, а каждый корень S3 должен быть доступен для чтения списка и не быть пустым.
5. **Повторная проверка данных.** Публикуемый `dataset.csv` проверяется заново с открытием каждого изображения. В нём не должно быть блокирующих условий ([blocker](../../GLOSSARY.md)), структурных ошибок, отклонённых строк и исправлений. Затем заново проверяется исходный `sources/dataset.csv`: если ему нужна очистка, она должна была быть разрешена флагом `--clean` при подготовке.
6. **Повторный вывод результата.** Из исходных файлов заново строятся очищенные строки и список задач датасета ([task manifest](../../GLOSSARY.md)). Результат должен побайтно совпасть с `dataset.csv`, `dataset.yaml` и `tasks.yaml` каталога.
7. **Ещё раз родитель.** Прямо перед публикацией родитель проверяется ещё раз (шаг 2), потому что предыдущие шаги могут идти долго.
8. **Публикация.** В ClearML создаётся новый датасет с тем же проектом и именем, родитель — найденный родительский датасет (или без родителя, если его нет). Из новой версии удаляются унаследованные от родителя файлы, затем добавляются ровно три файла: `dataset.csv`, `dataset.yaml`, `tasks.yaml`. Команда загружает их без повторных попыток, проверяет список файлов, завершает (finalize) версию и проверяет список ещё раз.

Изображения в ClearML не загружаются: публикуются только три файла. Каталог `prepared_dir`, CVAT и S3 команда не меняет. Шаги 1–7 ничего не создают в ClearML.

## Результат

После успешной публикации команда печатает ID нового датасета и версию, которую назначил ClearML:

```text
Опубликован датасет 1a2b3c4d5e6f47a8b9c0d1e2f3a4b5c6, версия 1.0.2.
```

ClearML SDK печатает свои строки о загрузке файлов, например `Uploading dataset changes (3 files compressed to 2.92 KiB) …`.

Если ClearML не вернул номер версии, вместо него печатается `назначена сервером`.

### Коды завершения

| Код | Когда |
|---|---|
| 0 | Версия создана, загружена и завершена. |
| 1 | Публикация прервана (Ctrl+C). |
| 2 | Любая проверка не прошла; ошибка ClearML, S3 или API классов; каталог не готов к публикации. |

## Что блокирует публикацию

| Сообщение | Причина | Что делать |
|---|---|---|
| `Expected a regular, nonsymlink file: output/prepared-1/preparation.json` | Подготовка не была готова (`ready: false`), поэтому `preparation.json` не создан, или указан не тот каталог. | Посмотрите `report.json`, исправьте данные или добавьте `--clean` и подготовьте заново. |
| `Prepared files changed (hash mismatch); prepare again.` | Файл в каталоге изменён после подготовки. | Подготовьте датасет заново в новый каталог. |
| `Preparation record changed (hash mismatch); prepare again.` | Изменён `preparation.json`. | Подготовьте заново. |
| `Latest parent changed; подготовьте датасет заново.` | После подготовки в ClearML появилась новая версия этого датасета (например, вы опубликовали другой подготовленный каталог). | Подготовьте заново: новая подготовка возьмёт новую версию как родителя. |
| `Class identities changed; подготовьте датасет заново.` | Классы в API изменились после подготовки. | Подготовьте заново, при необходимости с `--accept-class-changes`. |
| `Корни изображений изменились; подготовьте датасет заново.` | Корни изображений после повторной проверки отличаются от записанных. | Подготовьте заново. |
| `Укажите разрешённые каталоги изображений:` и список путей | Изображение из `image_path` больше не лежит внутри записанных локальных корней. | Подготовьте заново с нужным `--local-root`. |
| `S3 root prefix does not exist or is empty: s3://my-bucket/images` | Корень S3 из `dataset.yaml` пуст или удалён. | Проверьте бакет и подготовьте заново. |
| `Подготовленные данные больше не проходят проверку: …` | Повторная проверка публикуемого `dataset.csv` нашла проблемы, например изображение удалено или изменено. | Исправьте изображения и подготовьте заново. |
| `Исходные данные больше не проходят проверку; подготовьте датасет заново.` | Повторная проверка исходного `dataset.csv` нашла блокирующее условие или структурную ошибку. | Подготовьте заново. |
| `Очистка исходных данных не была разрешена.` | Исходным данным нужна очистка, а при подготовке не было `--clean`. | Подготовьте заново с `--clean`. |
| `Результат повторной проверки изменился; подготовьте датасет заново.` | Повторный вывод дал другие очищенные строки или другой список задач. | Подготовьте заново. |

Все сообщения выводятся с префиксом `Ошибка публикации:`.

## Сбой во время публикации

Если ошибка случилась после того, как новый датасет создан в ClearML (шаг 8), команда называет его ID:

```text
Ошибка публикации: Publication failed for created ClearML dataset <id>; inspect it before retrying; check ClearML configuration, credentials and connectivity (…)
```

Созданная версия остаётся в ClearML незавершённой. Родительский датасет при этом не меняется, а при поиске родителя учитываются только завершённые версии. Поэтому после устранения причины можно снова запустить `cveta2 upload-dataset` для того же каталога: повторный запуск создаёт и завершает новую версию. Незавершённую версию cveta2 не удаляет; проверьте и удалите её в ClearML сами.

При прерывании (Ctrl+C) после создания датасета команда печатает:

```text
Публикация отменена: Publication interrupted for ClearML dataset <id>; its remote state is uncertain. Inspect it before retrying.
```

и завершается с кодом 1. Проверьте этот датасет в ClearML перед повторным запуском.

## Интерактивный и неинтерактивный режим

Команда ничего не спрашивает. Все решения принимаются при подготовке в [`verify --bundle`](verify.md#интерактивный-и-неинтерактивный-режим). `CVETA2_NO_INTERACTIVE` на неё не влияет.

## Из Python

```python
def upload_dataset(prepared_dir: str | Path) -> Publication
```

Функция `cveta2.upload_dataset` делает те же проверки и публикацию, что и команда. Она возвращает `cveta2.Publication` с полями `dataset_id` и `version` (`None`, если ClearML не вернул версию). Ошибки — подклассы `cveta2.Cveta2Error`.

```python
import cveta2

prepared = cveta2.prepare_dataset(
    "output/fetch",
    output_dir="output/prepared-1",
    options=cveta2.PrepareOptions(
        project="Retail/Datasets",
        dataset_name="retail-shelves",
        api_url="https://classes.example.com/api",
        local_roots=("/home/user/data/images",),
        accept_default_classes=True,
        clean=True,
    ),
)
if prepared.ready:
    publication = cveta2.upload_dataset(prepared.directory)
    print(publication.dataset_id, publication.version)
```

Подробнее об API — на странице [Python API](../python-api.md).
