# cveta2 setup-cache

Команда задаёт в личной конфигурации ([personal configuration](../../GLOSSARY.md)), куда складывать изображения каждого проекта и где хранить локальный кэш аннотаций ([annotation cache](../../GLOSSARY.md)). Запустите её один раз после `cveta2 setup` или когда появился новый проект.

## Примеры

Пройти все вопросы мастера в терминале:

```bash
cveta2 setup-cache
```

Посмотреть текущие пути кэша и выйти, ничего не меняя:

```bash
cveta2 setup-cache --list
```

Заново предложить для каждого проекта путь `<корень>/<имя проекта>`, не глядя на уже сохранённые пути:

```bash
cveta2 setup-cache --reset
```

## Синтаксис и аргументы

```text
cveta2 setup-cache [-h] [--config CONFIG] [--reset] [--list]
```

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--config CONFIG` | `CVETA2_CONFIG`, иначе `~/.config/cveta2/config.yaml` | Путь к файлу личной конфигурации, который команда читает и меняет. |
| `--reset` | выключен | Для каждого проекта предлагать по умолчанию путь `<корень кэша>/<имя проекта>`, даже если путь проекта уже задан. Без корня кэша значения по умолчанию нет. |
| `--list` | выключен | Напечатать текущие настройки кэша и выйти. Работает без терминала и без CVAT. |
| `-h`, `--help` | | Показать справку. |

## Как это работает

С `--list` команда только читает секции `image_cache` и `cache` и печатает их (см. «Результат»). Если подключена общая конфигурация, `ignored_prefix` и `task_cache_s3` проектов берутся из неё, а ошибка в файле общей конфигурации прерывает и `--list`.

Без `--list`:

1. Если задано `CVETA2_NO_INTERACTIVE=true`, сразу завершается с ошибкой. Закрытый стандартный ввод обнаруживается позже, на первом вопросе (шаг 3), то есть уже после шага 2.
2. Берёт список проектов из файла `projects.yaml` в каталоге личной конфигурации. Если список пуст, подключается к CVAT, загружает проекты организации и сохраняет их в `projects.yaml`. Если проектов нет, завершается ошибкой `Нет доступных проектов.`
3. Спрашивает корневую директорию кэша. Пустой ответ означает «без корня».
4. Если корень указан, печатает для каждого проекта путь `проект -> путь` и спрашивает, применить ли их ко всем проектам. Путь по умолчанию — уже сохранённый путь проекта, а если его нет (или задан `--reset`) — `<корень>/<имя проекта>`. Символы `/`, `\` и `%` в имени проекта кодируются (`%2F`, `%5C`, `%25`).
5. Если корня нет или вы ответили «нет», спрашивает путь отдельно для каждого проекта. Enter принимает путь по умолчанию. Если значения по умолчанию нет, проект пропускается.
6. Сохраняет пути проектов в секцию `image_cache`, если что-то изменилось.
7. Если корень указан, записывает его в `cache.images_root`.
8. Спрашивает каталог локального кэша аннотаций. Пустой ответ оставляет текущее значение; если значения нет, используется `~/.cache/cveta2/task_annotations`. Ответ записывается в `cache.tasks_root`.
9. Спрашивает, настроить ли `ignored_prefix` и `task_cache_s3` по проектам (по умолчанию «нет»). При «да» для каждого проекта спрашивает отбрасываемый префикс ([ignored prefix](../../GLOSSARY.md)) и S3-путь кэша аннотаций. Пустой ответ оставляет текущее значение. Если подключена общая конфигурация ([global configuration](../../GLOSSARY.md)), эти два значения берутся из неё, а изменённые ответы записываются в файл общей конфигурации, а не в личную.
10. Сохраняет секцию `cache`, если что-то изменилось, и печатает `Готово!`.

Команда не создаёт каталоги и не скачивает изображения. Каталоги появляются при первом `cveta2 fetch` или `cveta2 s3-sync`. Что означают эти настройки и как файлы раскладываются на диске, описано в [Кэш изображений и аннотаций](../images-and-cache.md). Ключи конфигурации описаны в [Конфигурация](../configuration.md).

## Результат

Команда меняет файл личной конфигурации (секции `image_cache` и `cache`), файл общей конфигурации (только если вы изменили `ignored_prefix` или `task_cache_s3` при подключённой общей конфигурации) и, если списка проектов не было, создаёт `projects.yaml` рядом с ним.

`--list` печатает по строке на каждую настройку:

```text
  Retail shelves: /home/user/data/images/Retail shelves
  images_root: /home/user/data/images
  tasks_root: /home/user/data/task_annotations
  Retail shelves: ignored_prefix: images
  Retail shelves: task_cache_s3: s3://my-bucket/cveta2-cache
```

Если для проекта в `cache.projects` заданы свои `images_root` или `tasks_root`, они печатаются так же: `Retail shelves: images_root: ...`.

Если ничего не задано:

```text
Пути кэша не заданы.
```

### Коды завершения

| Код | Когда |
|---|---|
| `0` | Настройки сохранены или напечатаны (`--list`). |
| `1` | Нет терминала, нет проектов, не удалось подключиться к CVAT или файл конфигурации содержит ошибку (в том числе при `--list`). |

## Интерактивный и неинтерактивный режим

Без `--list` команда полностью интерактивная. Вопросы по порядку:

| Вопрос | Ответ по умолчанию |
|---|---|
| `Корневая директория кэша (по умолчанию для проектов: корень/имя_проекта) []:` | пусто (без корня) |
| `Применить ко всем проектам?` (только если корень задан) | да |
| `<проект> (id=<ID>) [<путь>]:` для каждого проекта (без значения по умолчанию: `[не задан]`) | показанный путь |
| `Локальный кэш аннотаций задач [<путь>]:` | текущее значение |
| `Настроить ignored_prefix / task_cache_s3 по проектам?` | нет |
| `<проект>: игнорируемый префикс S3 [<значение>]:` | текущее значение |
| `<проект>: S3-путь кэша задач [<значение>]:` | текущее значение; если его нет — `<префикс изображений>/.cveta2_cache` |

При `CVETA2_NO_INTERACTIVE=true` работает только `--list`. Чтобы настроить кэш без терминала, впишите секции `image_cache` и `cache` в файл конфигурации сами (см. [Конфигурация](../configuration.md)).

## Частые ошибки

```text
Interactive prompt required but CVETA2_NO_INTERACTIVE=true. The 'setup-cache' command is fully interactive. Edit the config file directly to set image_cache paths.
```

Задано `CVETA2_NO_INTERACTIVE=true`. Запустите команду в терминале без этой переменной или отредактируйте конфигурацию вручную.

```text
Interactive prompt required but standard input is closed. The 'setup-cache' command is fully interactive. Edit the config file directly to set image_cache paths.
```

Команда запущена без терминала (из скрипта, CI). Решение то же.

```text
Нет доступных проектов.
```

В `projects.yaml` нет проектов, а CVAT не вернул ни одного. Проверьте организацию и права в `cveta2 doctor`.

## Из Python

Публичной функции для этой команды нет. Чтобы узнать, куда попадут изображения проекта, используйте `cveta2.config.resolve_images_cache_dir`:

```python
resolve_images_cache_dir(project_name: str, config_path: Path | None = None) -> Path | None
```

Функция возвращает путь из `image_cache.<проект>`, иначе `<images_root>/<имя проекта>` (сначала `cache.projects.<проект>.images_root`, потом `cache.images_root`; имя кодируется так же, как в шаге 4), иначе `None`.

```python
from cveta2.config import resolve_images_cache_dir

print(resolve_images_cache_dir("Retail shelves"))
```

Подключение и остальной API описаны в [Python API](../python-api.md).
