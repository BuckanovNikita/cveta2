# cveta2 s3-sync

Скачивает в кэш изображений ([image cache](../../GLOSSARY.md)) все файлы из S3-хранилища проекта (или только из корня синхронизации, если он задан), а не только изображения с аннотациями. Нужна, чтобы заранее получить локальную копию всех изображений проекта, например перед работой без сети.

## Примеры

Скачать недостающие файлы одного проекта:

```bash
cveta2 s3-sync -p "Retail shelves"
```

Синхронизировать все проекты, для которых в конфигурации задан кэш изображений:

```bash
cveta2 s3-sync
```

Один раз взять файлы из другого места в S3:

```bash
cveta2 s3-sync -p "Retail shelves" --root s3://my-bucket/images/2026
```

## Синтаксис и аргументы

```text
cveta2 s3-sync [-h] [--project PROJECT] [--root ROOT]
```

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--project`, `-p` | все проекты из конфигурации | Проект: ID, имя или `ORG/PROJECT`. Без него синхронизируются все проекты из конфигурации, у которых есть каталог кэша изображений (см. «Как это работает»). |
| `--root` | из конфигурации | Корень синхронизации ([sync root](../../GLOSSARY.md)) на этот запуск: `s3://bucket/prefix` или префикс в бакете проекта. Важнее корня синхронизации из конфигурации (`projects.<ключ>.sync_root` в общей конфигурации). Требует `-p`. |
| `-h`, `--help` | | Показать справку. |

## Как это работает

С `-p`:

1. Команда находит проект в CVAT и его облачное хранилище (cloud storage): бакет и префикс.
2. Если задан `--root` или для проекта задан корень синхронизации в конфигурации, бакет и префикс заменяются им. Команда печатает `корень синхронизации переопределён на s3://...`.
3. Каталог кэша изображений проекта берётся из `image_cache` или `cache.images_root` (см. [Кэш изображений](../images-and-cache.md#кэш-изображений)). Если он не настроен — ошибка.
4. Команда перечисляет все объекты под префиксом и скачивает те, которых нет локально. Подпапки ключей S3 сохраняются; если для проекта задан отбрасываемый префикс ([ignored prefix](../../GLOSSARY.md)), он убирается из локального пути (см. [Как ключи S3 превращаются в локальные пути](../images-and-cache.md#как-ключи-s3-превращаются-в-локальные-пути)).
5. Команда ничего не удаляет ни локально, ни в S3 и ничего не загружает в S3.

Без `-p`:

1. Команда берёт имена проектов из раздела `image_cache` и из `cache.projects` личной конфигурации. В `cache.projects` попадают и проекты общей конфигурации, у которых задан `ignored_prefix` или `task_cache_s3`. Проект остаётся в списке, только если для него получается каталог кэша: запись в `image_cache` или `cache.images_root`. Проекты, о которых конфигурация знает только через `cache.images_root`, в список не попадают: для них запускайте команду с `-p`.
2. Для каждого проекта выполняются шаги выше. Проект, который не удалось найти в CVAT или у которого нет облачного хранилища, пропускается с сообщением; остальные проекты продолжают синхронизироваться.
3. В конце печатается `Синхронизация неполная: пропущены проекты [...]`, если такие были.

Если какие-то файлы не скачались, команда завершается с ошибкой, но уже скачанные файлы остаются. Повторный запуск скачает только недостающие.

## Результат

Файлы появляются в каталоге кэша изображений проекта. Вывод:

```text
Проект 123: синхронизация из s3://my-bucket/images → ~/data/retail
S3 sync: 17 загружено, 8 из кэша, 0 ошибок (всего 25)
Проект 'Retail shelves': 17 загружено, 8 из кэша, 0 ошибок (всего 25)
```

В эти числа входят все объекты под префиксом, не только изображения. Если кэш аннотаций проекта хранится в S3 в месте по умолчанию, его файлы тоже скачиваются: в каталоге проекта появляется подкаталог `.cveta2_cache/` (см. [Изображения и кэши](../images-and-cache.md#кэш-изображений)).

Если всё уже скачано:

```text
Все 25 файлов уже загружены в ~/data/retail
Проект 'Retail shelves': 0 загружено, 25 из кэша, 0 ошибок (всего 25)
```

Если под префиксом нет объектов, команда печатает `Нет объектов в s3://...` и завершается с кодом 0.

### Коды завершения

| Код | Значение |
|---|---|
| `0` | Все файлы есть локально. Код 0 и тогда, когда у проекта нет облачного хранилища (с `-p` и без), и когда без `-p` часть проектов пропущена (не найдена в CVAT). |
| `1` | Ошибка: не настроен кэш изображений, `--root` без `-p`, проект не найден, ошибка S3, часть файлов не скачалась. |
| `2` | Неверные аргументы командной строки. |

## Интерактивный и неинтерактивный режим

Без `-p` команда ничего не спрашивает: она синхронизирует все проекты из конфигурации. С `-p` проект ищется в CVAT без вопросов. Поведение при `CVETA2_NO_INTERACTIVE=true` такое же.

## Частые ошибки

**`Ошибка: --root требует явного указания проекта через --project.`**

Добавьте `-p`.

**`Ошибка: нет проектов для синхронизации — не настроены ни image_cache, ни cache.projects.`**

В личной конфигурации нет проектов с кэшем изображений. Запустите команду с `-p` или настройте кэш: [setup](setup.md#мастер-личной-настройки).

**`Ошибка: для проекта 'Retail shelves' не настроен путь кэширования изображений.`**

Добавьте `image_cache.<проект>` или `cache.images_root` в [конфигурацию](../configuration.md), например `cveta2 setup --images-root PATH` или `cveta2 setup -p <проект> --images-dir PATH` (см. [setup](setup.md)).

**`Проект 'Retail shelves': cloud storage не найден — пропускаем.`**

У проекта в CVAT не задано облачное хранилище. Синхронизировать нечего.

**`Ошибка S3 (синхронизация s3://my-bucket/images): An error occurred (NoSuchBucket) ...`**

Бакета нет или нет доступа. Проверьте `--root`, `sync_root` проекта в общей конфигурации и доступ к S3.

**`Ошибка: проект 'Retail shelves': не удалось скачать 3 из 25 объектов из s3://my-bucket/images. Повторите s3-sync: скачанные файлы будут пропущены.`**

Часть файлов не скачалась. Повторите команду.

**`Project not found: 'Retail shelves'`**

Проверьте имя проекта и организацию (`my-team/Retail shelves`).

Если кадр CVAT записан как `hk-with-mem/a.jpg`, а префикс хранилища проекта — `hk`, проверьте выбор каталога при создании задачи. `s3-sync` перечисляет только объекты под `hk/`. При загрузке кадра `fetch` сначала ищет точный относительный путь `hk/hk-with-mem/a.jpg`. Если такого объекта нет, команда предупреждает о возможном соседнем префиксе и учитывает кадр как ошибку загрузки. Проверьте привязанное облачное хранилище и `sync_root` проекта. Для новой задачи выбирайте файлы внутри каталога нужного проекта.

## Из Python

```python
cveta2.s3_sync(
    project: int | str,
    target_dir: str | Path,
    *,
    root: str | None = None,
    connection: Connection | None = None,
) -> DownloadStats
```

Синхронизирует один проект в каталог `target_dir` (каталог кэша из конфигурации здесь не используется). Отбрасываемый префикс и корень синхронизации берутся из конфигурации; `root` важнее корня из конфигурации. Возвращает `DownloadStats` с полями `downloaded`, `cached`, `failed`, `total`. Нескачанные файлы не вызывают исключение: проверьте `failed`. Если у проекта нет облачного хранилища, возвращается `total=0`.

Исключения (подклассы `cveta2.Cveta2Error`): проект не найден, неверный корень синхронизации, ошибки CVAT и S3.

```python
import cveta2

stats = cveta2.s3_sync("Retail shelves", "output/images")
print(stats.downloaded, stats.cached, stats.failed, stats.total)
```

Как задать подключение — в [Python API](../python-api.md).
