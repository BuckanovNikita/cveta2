# cveta2 fetch

Выгружает bbox-аннотации всех задач (task) проекта CVAT в CSV и скачивает изображения из S3. Это полная выгрузка ([full fetch](../../GLOSSARY.md)): она нужна, чтобы получить актуальный датасет проекта.

> Флаг `--skip-validation` меняет job в CVAT: переводит их на stage `acceptance`. Команда не возвращает их обратно.

## Примеры

Выгрузить проект по имени вместе с изображениями:

```bash
cveta2 fetch -p "Retail shelves" -o output/
```

Выгрузить проект по ID, без изображений:

```bash
cveta2 fetch -p 123 -o output/ --no-images
```

Выгрузить проект из другой организации, положить изображения в свой каталог и дополнительно сохранить сырой CSV:

```bash
cveta2 fetch -p "my-team/Retail shelves" -o output/ --images-dir ~/data/retail --raw
```

## Синтаксис и аргументы

```text
cveta2 fetch [-h] [--project PROJECT] [--skip-validation] --output-dir OUTPUT_DIR [--raw] [--completed-only] [--no-images] [--images-dir IMAGES_DIR] [--save-tasks] [--no-cache] [--force]
```

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--project`, `-p` | выбор в терминале | Проект: ID, имя или `ORG/PROJECT`. Подробно — в разделе «Как выбирается проект» ниже. |
| `--output-dir`, `-o` | обязателен | Каталог для CSV. Если его нет, он создаётся. |
| `--raw` | выкл. | Дополнительно записать сырой CSV ([raw output](../../GLOSSARY.md)) `raw.csv`. |
| `--completed-only` | выкл. | Выгружать только задачи, у которых в CVAT статус задачи `completed`. |
| `--skip-validation` | выкл. | Перед выгрузкой принять в CVAT готовую разметку: см. шаг 2 в «Как это работает». |
| `--no-images` | выкл. | Не скачивать изображения из S3. |
| `--images-dir` | из конфигурации | Каталог для изображений на этот запуск. Важнее настроек конфигурации. Вместе с `--no-images` не действует: изображения не скачиваются. |
| `--save-tasks` | выкл. | Записать CSV каждой задачи в `<output-dir>/.tasks/task_<id>.csv`. |
| `--no-cache` | выкл. | Не читать и не записывать кэш аннотаций. |
| `--force` | выкл. | Скачать аннотации всех задач заново с CVAT и обновить кэш аннотаций. |
| `-h`, `--help` | | Показать справку. |

### Как выбирается проект

- Число (`-p 123`) — ID проекта.
- Текст (`-p "Retail shelves"`) — имя проекта в организации из конфигурации. Регистр букв не важен.
- `ORG/PROJECT` (`-p "my-team/Retail shelves"`) — проект в организации `my-team`. Организация из конфигурации на этот запуск не используется.
- `/PROJECT` (`-p "/Retail shelves"`) — проект в личном пространстве (без организации).
- Если в организации несколько проектов с таким именем, команда останавливается с ошибкой и перечисляет их ID. Укажите проект по ID.

## Как это работает

1. Если папка `--output-dir` уже существует, в неинтерактивном режиме команда пишет в неё поверх. В терминале она спрашивает, что делать (см. ниже).
2. Только с `--skip-validation`: команда проходит по всем задачам проекта, кроме задач из списка игнорируемых задач ([ignore list](../../GLOSSARY.md)). Если у задачи все job имеют state `completed`, а stage `annotation` или `acceptance`, то job на stage `annotation` переводятся на stage `acceptance` с state `completed`. Перед этим удаляется запись задачи в кэше аннотаций. Если хотя бы одна задача не прошла этот шаг, выгрузка не начинается, а уже сделанные изменения в CVAT остаются.
3. Команда читает список задач проекта и метки (label) проекта. Задачи из списка игнорируемых задач пропускаются, для каждой печатается предупреждение (кроме задач с `--silent`, см. [ignore](ignore.md)). С `--completed-only` остаются только задачи со статусом `completed`.
4. Для каждой задачи команда читает job с CVAT. Метаданные кадров (frame), issues и аннотации берутся из кэша аннотаций ([annotation cache](../../GLOSSARY.md)), если задача и её job не изменились; иначе скачиваются с CVAT. Несколько задач обрабатываются одновременно.
5. Из аннотаций берутся только фигуры (shape) двух типов:
   - прямоугольник (rectangle) попадает в CSV как есть;
   - полигон (polygon) заменяется описанным вокруг него прямоугольником, команда печатает предупреждение. Полигон с меньше чем тремя точками или нулевой шириной/высотой пропускается.

   Остальные типы фигур пропускаются с предупреждением `Skipping shape type <type> as it's not supported.`. Фигуры на кадрах без метаданных тоже пропускаются. Если аннотации задачи взяты из кэша, предупреждения о типах фигур и полигонах не печатаются повторно.
6. С `--save-tasks` CSV каждой непустой задачи записывается в `.tasks/`.
7. Из кэша аннотаций удаляются записи задач, которых больше нет в проекте.
8. Если изображения не отключены, команда скачивает изображения из облачного хранилища (cloud storage) проекта в кэш изображений ([image cache](../../GLOSSARY.md)). Уже скачанные файлы пропускаются. Каталог выбирается так: `--images-dir`, иначе настройки `image_cache` или `cache.images_root` из конфигурации (см. [Кэш изображений](../images-and-cache.md#кэш-изображений)).
9. С `--raw` записывается `raw.csv`.
10. Строки раскладываются по четырём файлам полной выгрузки ([partition outputs](../../GLOSSARY.md)): `dataset.csv`, `obsolete.csv`, `in_progress.csv`, `deleted.csv`. Какая строка в какой файл попадает, зависит от того, завершена ли задача ([completed task](../../GLOSSARY.md)); правило описано в [Формат данных](../dataset-format.md#файлы-полной-выгрузки).
11. Рядом с CSV записывается черновик `dataset.yaml` ([dataset draft](../../GLOSSARY.md)). Если в конфигурации задан API классов, команда читает реестр классов и проверяет покрытие классов. См. [Черновик dataset.yaml](#черновик-datasetyaml).

Команда ничего не пишет в S3, кроме кэша аннотаций, если он настроен в S3 (см. [Кэш аннотаций](../images-and-cache.md#кэш-аннотаций)). К ClearML она не обращается; кроме CVAT и S3, она делает только GET-запрос к API классов.

### Перезапись папки

Команда перезаписывает только те файлы, которые пишет в этом запуске. Старый `raw.csv` (если запуск без `--raw`) и папка `.tasks/` (если запуск без `--save-tasks`) остаются от прошлого запуска. Черновик `dataset.yaml` пишется заново при каждом запуске; прежний черновик с другим содержимым сохраняется как `dataset.yaml.bak` (см. [Черновик dataset.yaml](#черновик-datasetyaml)).

### Если CVAT отвечает ошибкой

- Ошибка 5xx на задаче: задача пропускается, печатается ошибка и подсказка, как добавить задачу в список игнорируемых задач. В конце печатается `Пропущены задачи (<N>): [<ID>]; выгрузка неполная`. Команда завершается с кодом 0. Чтобы выгрузка в этом случае прерывалась, задайте `CVETA2_RAISE_ON_FAILURE=true` (см. [Конфигурация](../configuration.md#переменные-окружения)).
- Ошибка 429 (CVAT ограничивает частоту запросов) после всех повторов: выгрузка прерывается. Уменьшите `network.cvat_workers` и повторите.
- Не удалось прочитать issues задачи: задача выгружается, столбцы `issue_text` и `issue_state` остаются пустыми, печатается предупреждение.
- Другая ошибка сети или CVAT после всех повторов: выгрузка прерывается, CSV не пишутся.

## Результат

В `--output-dir`:

| Файл | Когда |
|---|---|
| `dataset.csv`, `obsolete.csv`, `in_progress.csv`, `deleted.csv` | всегда (файл может быть пустым, только с заголовком) |
| `dataset.yaml` | всегда: черновик для `verify`, см. [ниже](#черновик-datasetyaml) |
| `dataset.yaml.bak` | если прежний `dataset.yaml` отличался от нового |
| `raw.csv` | с `--raw` |
| `.tasks/task_<id>.csv` | с `--save-tasks`, для задач с аннотациями |

Столбцы файлов описаны в [Формат данных](../dataset-format.md). Если изображения скачаны, столбец `image_path` содержит локальный путь к файлу.

Если после отбора не осталось ни одной задачи (например, с `--completed-only` в проекте нет завершённых задач), команда печатает `Нет задач для выгрузки.`, пишет файлы только с заголовком и завершается с кодом 0.

Команда печатает время каждого этапа и итоги, например:

```text
Отбор задач: 8 к загрузке; прошло 0.4 с
Обработка задач: прошло 0.4 с; из кэша: 5, загружено с CVAT: 3, пропущено: 0, неполные issues: 0. ...
Изображения: 8 загружено, 0 из кэша, 0 ошибок (всего 8); прошло 0.1 с
Dataset CSV saved to output/dataset.csv (8 images, 30 rows)
Obsolete CSV saved to output/obsolete.csv (8 images, 86 rows)
In-progress CSV saved to output/in_progress.csv (8 images, 50 rows)
Deleted CSV saved to output/deleted.csv (0 images, 0 rows)
Выгрузка завершена: прошло 1.0 с
```

Если проект или папка были выбраны в терминале, команда дополнительно печатает строку `Команда для повторного запуска:` и полную команду со всеми аргументами. Ответ на вопрос о каталоге изображений эту строку не вызывает.

### Черновик dataset.yaml

Полная выгрузка пишет в `--output-dir` черновик `dataset.yaml`: всё, что о публикации набора известно из глобальной конфигурации и из этого запуска. Команда `verify <каталог>` берёт значения из черновика, а не из конфигурации: каталог выгрузки самодостаточен, и черновик можно поправить перед подготовкой. Пример:

```yaml
clearml:
  project: Retail/Datasets
  dataset: retail-shelves
  output_uri: s3://my-bucket/.clearml
api_url: https://classes.example.com/api
empty_classes: [12]
images:
  local_root:
    - /home/alice/data/images/Retail shelves
  s3_root:
    - s3://my-bucket/images
```

Откуда берётся каждый ключ:

| Ключ | Источник |
|---|---|
| `clearml.project`, `clearml.dataset`, `api_url`, `empty_classes` | `projects.<ключ>.publication` выгруженного проекта (проект ищется по ID проекта CVAT) |
| `clearml.output_uri` | `publication.clearml.output_uri`, иначе `s3://<bucket>/.clearml` с bucket, из которого этот запуск брал изображения (облачное хранилище проекта или корень синхронизации, если он задан), иначе ключа нет (ClearML использует свой файловый сервер) |
| `images.local_root` | каталог кэша изображений этого запуска (`--images-dir`, иначе из конфигурации); с `--no-images` ключа нет |
| `images.s3_root` | `publication.s3_roots`, иначе `s3://<bucket>/<prefix>` хранилища, из которого этот запуск брал изображения |

Форма `s3://<bucket>/.clearml` одна и та же для AWS и для своего S3-совместимого сервера, например MinIO. Адрес сервера ClearML получает отдельно (`AWS_ENDPOINT_URL_S3` или запись учётных данных в `clearml.conf`), так же, как для S3-корней. Проверить настройку ClearML можно командой [`cveta2 doctor`](doctor.md).

Любой ключ черновика необязателен: команда пишет то, что знает. Черновик пишется заново при каждом запуске, как и CSV. Если прежний `dataset.yaml` отличается от нового (например, вы его правили), он сохраняется как `dataset.yaml.bak`, старая копия `.bak` заменяется, и команда печатает `Прежний dataset.yaml отличался и сохранён как dataset.yaml.bak.`

Для каждого пробела в черновике команда печатает предупреждение с подсказкой:

| Пробел | Как исправить |
|---|---|
| у проекта нет настроек `publication` | `cveta2 setup --global --project '<проект>' --clearml-project … --dataset-name … --api-url …` (см. [setup](setup.md)), или передайте значения флагами `cveta2 verify` |
| нет локального каталога изображений (`--no-images`) | передайте его при подготовке: `cveta2 verify --local-root <каталог>` |
| в `dataset.csv` есть строки с пустым `image_path` | команда печатает их число: подготовка (`cveta2 verify`) остановится на них. Скачайте изображения: [`cveta2 s3-sync`](s3-sync.md) или `fetch` без `--no-images` |

Если `api_url` известен, команда читает реестр классов и сравнивает с ним метки `dataset.csv` (по текущим именам классов; переименования учитывает `verify`):

- строки классов из `empty_classes` (исключённых классов): печатается их число, `verify` отбросит их при очистке;
- классы, которые не исключены, но не имеют ни одного bbox в `dataset.csv`: печатаются их имена. Добавьте данные с этими классами или отметьте их `empty: true` (номер класса в `empty_classes`), иначе `verify` остановится;
- номера из `empty_classes`, которых нет в реестре классов (опечатка или удалённый класс): печатаются номера, `verify` остановится на них.

Если API классов недоступен или его ответ нельзя использовать (некорректный адрес, повторяющиеся классы), команда печатает одно предупреждение и пропускает проверку классов. Если черновик не удалось записать, команда тоже печатает предупреждение. Ни одно из этих предупреждений не меняет код завершения: CSV уже записаны, выгрузка считается завершённой.

### Коды завершения

| Код | Значение |
|---|---|
| `0` | Выгрузка завершена (в том числе если задачи с ошибкой 5xx пропущены, а также с предупреждениями о черновике `dataset.yaml` и о классах). |
| `1` | Ошибка: общая конфигурация некорректна (в том числе блок `publication`), проект не найден, не настроен каталог изображений, ошибка CVAT или S3, нужен ввод в неинтерактивном режиме. |
| `2` | Неверные аргументы командной строки (например, нет `-o`). |

## Интерактивный и неинтерактивный режим

В терминале команда спрашивает:

- проект, если нет `-p`. Список проектов показан по организациям, первой идёт организация из конфигурации. Есть пункты «Следующая организация» и «Обновить список проектов с CVAT». Список кэшируется локально;
- что делать, если папка `-o` уже существует: «Перезаписать», «Указать другой путь» или «Отмена»;
- каталог изображений, если он не настроен и нет `--images-dir` и `--no-images`. Ответ сохраняется в личную конфигурацию как `image_cache.<проект>`. Пустой ответ — изображения не скачиваются.

С `CVETA2_NO_INTERACTIVE=true` (см. [Неинтерактивный режим](../configuration.md#неинтерактивный-режим)):

- нужен `-p`;
- существующая папка `-o` перезаписывается, команда печатает `Папка output уже существует — перезапись (неинтерактивный режим).`;
- нужен `--images-dir`, `--no-images` или настроенный каталог изображений.

## Частые ошибки

**`Project not found: 'Retail shelves'`**

Проекта с таким именем нет в выбранной организации. Проверьте имя и организацию. Для проекта в другой организации укажите `my-team/Retail shelves`, для личного пространства — `/Retail shelves`.

**`Имя проекта 'Retail shelves' неоднозначно: id=[123, 124]. Укажите числовой ID проекта.`**

В организации несколько проектов с этим именем. Укажите ID: `-p 123`.

**`Некорректная спецификация проекта '/': ожидается ORG/PROJECT или /PROJECT.`**

После `/` нет имени проекта.

**`... detail: my-team organization does not exist.`**

Организации из префикса `ORG/` нет на сервере или у вас нет к ней доступа.

**`Ошибка: путь кэширования изображений для проекта 'Retail shelves' не настроен.`**

Каталог изображений не задан. Добавьте `--images-dir` или `--no-images`, или настройте кэш: [setup](setup.md#мастер-личной-настройки).

**`Interactive prompt required but CVETA2_NO_INTERACTIVE=true. Pass --project / -p to specify the project ID or name.`**

В неинтерактивном режиме не указан `-p`.

**`Interactive prompt required but standard input is closed. Pass --output / -o to specify the output directory.`**

Команда запущена без терминала и без `CVETA2_NO_INTERACTIVE=true`, а папка `-o` уже существует. Задайте `CVETA2_NO_INTERACTIVE=true` или удалите папку. Флаг в подсказке называется `--output`, но у команды он `--output-dir` / `-o`.

**`CVAT ограничивает частоту запросов (HTTP 429) на задаче 456, повторы исчерпаны. ...`**

Уменьшите `network.cvat_workers` в [конфигурации](../configuration.md#сеть-и-повторы) и повторите.

## Из Python

```python
cveta2.fetch(
    project: int | str,
    output_dir: str | Path,
    *,
    completed_only: bool = False,
    skip_validation: bool = False,
    raw: bool = False,
    images_dir: str | Path | None = None,
    download_images: bool = True,
    cache: Literal["use", "refresh", "off"] = "use",
    save_tasks: bool = False,
    connection: Connection | None = None,
) -> PartitionResult
```

Работает как команда, но никогда ничего не спрашивает. Записывает те же файлы, включая черновик `dataset.yaml` с теми же предупреждениями (они не вызывают исключений), и возвращает `PartitionResult`: таблицы pandas `dataset`, `obsolete`, `in_progress` и списки `deleted_images`, `pending_deletions`, `reopened_deletions`. Таблица `in_progress` короче файла `in_progress.csv`: строки-отметки об удалении в файл добавляются из двух последних списков (см. [`PartitionResult`](../python-api.md)).

- `project` — ID, имя или `ORG/PROJECT`, как у `-p`.
- `cache`: `"use"` — обычный режим, `"refresh"` — как `--force`, `"off"` — как `--no-cache`.
- `download_images=False` — как `--no-images`.

Исключения (все — подклассы `cveta2.Cveta2Error`): проект не найден или имя неоднозначно; каталог изображений не настроен; передан `images_dir` вместе с `download_images=False`; недопустимое значение `cache`; ошибки CVAT и S3.

```python
import cveta2

result = cveta2.fetch("Retail shelves", "output/", download_images=False)
print(len(result.dataset), len(result.obsolete), len(result.in_progress))
```

Как задать подключение — в [Python API](../python-api.md).
