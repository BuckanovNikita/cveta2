# cveta2 task

Меняет одну задачу (task) в CVAT: помечает кадры (frame) удалёнными, удаляет аннотации одной метки (label), удаляет задачу или меняет stage и state всех её job. Нужна для правок задачи без интерфейса CVAT.

> **Внимание.** `task drop-label` и `task delete` нельзя отменить: удалённые аннотации и удалённую задачу cveta2 вернуть не может. `task mark-deleted` cveta2 тоже не умеет отменить.

## Примеры

Пометить удалёнными кадр 0 и изображение `shelf_0025.jpg` в задаче 456:

```bash
cveta2 task mark-deleted -p "Retail shelves" -t 456 --frame 0 --image shelf_0025.jpg
```

Удалить все аннотации метки `orange` в задаче 456 без вопроса:

```bash
cveta2 task drop-label -p "Retail shelves" -t 456 --label orange --yes
```

Отметить задачу завершённой (все job: stage `acceptance`, state `completed`):

```bash
cveta2 task status -p "Retail shelves" -t 456 --stage acceptance --state completed
```

Удалить задачу целиком:

```bash
cveta2 task delete -p "Retail shelves" -t 456 --yes
```

## Общее для всех подкоманд

Все четыре подкоманды принимают `--project` (`-p`) и обязательный `--task` (`-t`):

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--project`, `-p` | выбор в терминале | ID или имя проекта. Можно указать организацию: `my-team/Retail shelves`; `/Retail shelves` выбирает личное пространство. |
| `--task`, `-t` | обязателен | ID или имя задачи. Число ищется сначала как ID, затем как имя. Имя сравнивается без учёта регистра. Если имя носят несколько задач, нужен ID. |
| `-h`, `--help` | | Показать справку. |

Каждая подкоманда работает так:

1. Подключается к CVAT, находит проект и задачу.
2. Выполняет своё изменение.
3. При выходе очищает запись задачи в кэше аннотаций ([annotation cache](../../GLOSSARY.md)): локальную и, если настроена, копию в S3. Если задача найдена, очистка выполняется всегда, даже если изменение упало или вы отказались от подтверждения. Следующая выгрузка прочитает задачу из CVAT заново. Где лежит кэш, описано на странице [Изображения и кэши](../images-and-cache.md).

Без терминала подкоманды работают только с `--project`, а `drop-label` и `delete` ещё и с `--yes`. Если проект выбран в терминале или действие подтверждено вопросом, команда печатает равносильную команду со всеми флагами, чтобы в следующий раз запустить её без вопросов.

### Коды завершения

Одинаковы для всех подкоманд:

| Код | Когда |
|---|---|
| 0 | Успех, в том числе когда менять было нечего. |
| 1 | Проект или задача не найдены, метка не найдена, не хватает флагов, нужен вопрос, а терминала нет, вы ответили «нет», ошибка CVAT. |
| 2 | Неверные аргументы командной строки, например недопустимое значение `--state` или нет `--task`. |

## mark-deleted

Помечает кадры задачи удалёнными в CVAT. Изображение остаётся в задаче, но выгрузка считает его удалённым.

### Синтаксис и аргументы

```text
cveta2 task mark-deleted [-h] [--project PROJECT] --task TASK [--frame N [N ...]] [--image NAME [NAME ...]]
```

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--project`, `-p` | выбор в терминале | Проект, см. выше. |
| `--task`, `-t` | обязателен | Задача, см. выше. |
| `--frame N [N ...]` | | Номера кадров в задаче, с 0. |
| `--image NAME [NAME ...]` | | Имена изображений в задаче. |

Нужен хотя бы один из `--frame` и `--image`. Их можно указать вместе.

### Как это работает

1. Имена из `--image` переводятся в номера кадров по данным задачи в CVAT. Имена, которых нет в задаче, пропускаются с предупреждением.
2. Номера из `--frame` вне диапазона задачи пропускаются с предупреждением.
3. Новые номера добавляются к уже удалённым кадрам задачи в CVAT. Кадр, который уже удалён, не считается повторно.
4. Аннотации удалённых кадров в CVAT не удаляются.
5. Запись задачи в кэше аннотаций очищается.

После этого [`fetch-task`](fetch-task.md) пишет каждый удалённый кадр в `deleted.csv` строкой с `instance_shape` = `deleted`. Как выгрузка учитывает удаления, описано на странице [Формат датасета](../dataset-format.md).

Подтверждение не спрашивается. Отменить отметку cveta2 не умеет.

### Результат

```text
Задача 456: изображения ['missing.jpg'] не найдены в задаче — пропускаем
Помечено удалёнными 1 кадров в задаче 456
Задача 456: кадры [9] не найдены (в задаче 3 кадров) — пропускаем
Помечено удалёнными 1 кадров в задаче 456
Задача 'shelves-batch-07' (id=456): помечено удалёнными кадров: 2
```

Число в последней строке — сколько кадров стали удалёнными за этот запуск. Если все кадры уже были удалены, оно равно 0.

### Частые ошибки

```text
Ошибка: укажите хотя бы один --frame или --image.
```

Добавьте `--frame` или `--image`.

```text
Task not found: '999'. Available tasks: 'shelves-batch-07' (id=456), ...
```

Задачи нет в проекте. Возьмите ID или имя из списка. Задачи из списка игнорируемых задач ([ignore list](../../GLOSSARY.md)) здесь тоже видны: подкоманды `task` его не читают.

### Из Python

```python
cveta2.task_mark_deleted(project, task, *, frames=None, images=None, connection=None) -> int
```

Возвращает число кадров, которые стали удалёнными. Без `frames` и `images` поднимает `cveta2.Cveta2Error`. Не найденные проект и задача поднимают `cveta2.ProjectNotFoundError` и `cveta2.TaskNotFoundError`.

```python
import cveta2

marked = cveta2.task_mark_deleted("Retail shelves", 456, frames=[0], images=["shelf_0025.jpg"])
print(marked)
```

## drop-label

Удаляет из одной задачи все фигуры (shapes) с указанной меткой. Сама метка остаётся в проекте.

> **Внимание.** Удаление аннотаций необратимо. cveta2 не может их восстановить. Чтобы сохранить копию, сначала выгрузите задачу через [`fetch-task`](fetch-task.md).

### Синтаксис и аргументы

```text
cveta2 task drop-label [-h] [--project PROJECT] --task TASK --label LABEL [--yes]
```

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--project`, `-p` | выбор в терминале | Проект, см. выше. |
| `--task`, `-t` | обязателен | Задача, см. выше. |
| `--label` | обязателен | Имя метки. Регистр важен: `Orange` и `orange` — разные метки. |
| `--yes`, `-y` | выкл. | Не спрашивать подтверждение. |

### Как это работает

1. Команда ищет метку среди меток задачи. Если её нет, команда завершается с ошибкой и печатает доступные метки.
2. Команда читает аннотации задачи и считает фигуры с этой меткой. Если их 0, она печатает сообщение и завершается с кодом 0.
3. Без `--yes` команда спрашивает «Удалить N аннотаций с меткой ... из задачи ...? [y/N]». По умолчанию ответ «нет». Ответ «нет» завершает команду с сообщением `Отменено.` и кодом 1.
4. Команда удаляет найденные фигуры в CVAT.
5. Запись задачи в кэше аннотаций очищается.

Удаляются только фигуры (shapes). Теги и треки с этой меткой не удаляются.

### Результат

```text
Удалено 4 аннотаций с меткой 'orange' из задачи 456
Задача 'shelves-batch-07' (id=456): удалено аннотаций: 4
```

Если удалять нечего:

```text
В задаче 'shelves-batch-07' (id=456) нет аннотаций с меткой 'person'.
```

### Частые ошибки

```text
Метка 'Orange' не найдена в задаче 456. Доступные метки: apple, bowl, orange, ...
```

Метки с таким именем в задаче нет. Проверьте написание и регистр.

```text
Interactive prompt required but CVETA2_NO_INTERACTIVE=true. Запустите команду с флагом --yes.
```

Без терминала подтвердить нельзя. Добавьте `--yes`.

### Из Python

```python
cveta2.task_drop_label(project, task, label, *, connection=None) -> int
```

Возвращает число удалённых фигур. Подтверждение не спрашивается: функция удаляет сразу. Метка, которой нет в задаче, поднимает `cveta2.Cveta2Error`.

```python
import cveta2

deleted = cveta2.task_drop_label("Retail shelves", 456, "orange")
print(deleted)
```

## delete

Удаляет задачу из CVAT целиком: с её кадрами, job и аннотациями.

> **Внимание.** Удаление задачи необратимо. cveta2 не может её восстановить.

### Синтаксис и аргументы

```text
cveta2 task delete [-h] [--project PROJECT] --task TASK [--yes]
```

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--project`, `-p` | выбор в терминале | Проект, см. выше. |
| `--task`, `-t` | обязателен | Задача, см. выше. |
| `--yes`, `-y` | выкл. | Не спрашивать подтверждение. |

### Как это работает

1. Без `--yes` команда спрашивает «Удалить задачу ... безвозвратно? [y/N]». По умолчанию ответ «нет». Ответ «нет» завершает команду с сообщением `Отменено.` и кодом 1.
2. Команда удаляет задачу в CVAT.
3. Запись задачи в кэше аннотаций очищается.

Изображения в S3 команда не трогает. Список игнорируемых задач она тоже не меняет: запись об удалённой задаче уберите сами через [`cveta2 ignore --remove`](ignore.md) по её ID.

### Результат

```text
Задача 456 удалена
Задача 'shelves-batch-07' (id=456) удалена.
```

После этого выгрузка задачи завершится ошибкой `Task not found`.

### Частые ошибки

```text
Interactive prompt required but CVETA2_NO_INTERACTIVE=true. Запустите команду с флагом --yes.
```

Без терминала подтвердить нельзя. Добавьте `--yes`.

```text
Task not found: '456'. Available tasks: ...
```

Задачи нет в проекте, например она уже удалена.

### Из Python

```python
cveta2.task_delete(project, task, *, connection=None) -> None
```

Удаляет задачу сразу, без подтверждения. Не найденная задача поднимает `cveta2.TaskNotFoundError`.

```python
import cveta2

cveta2.task_delete("Retail shelves", 456)
```

## status

Ставит одинаковые stage и (или) state всем job задачи. Статус задачи CVAT выводит из статусов её job. Так задачу можно сделать завершённой ([completed task](../../GLOSSARY.md)) или вернуть в работу.

### Синтаксис и аргументы

```text
cveta2 task status [-h] [--project PROJECT] --task TASK [--stage {annotation,validation,acceptance}] [--state {completed,in-progress,new,rejected}]
```

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--project`, `-p` | выбор в терминале | Проект, см. выше. |
| `--task`, `-t` | обязателен | Задача, см. выше. |
| `--stage` | не меняется | Stage job: `annotation`, `validation` или `acceptance`. |
| `--state` | не меняется | State job: `new`, `in-progress`, `completed` или `rejected`. Значение `in-progress` записывается в CVAT как `in progress`. |

Нужен хотя бы один из `--stage` и `--state`. Не указанное поле у job не меняется.

### Как это работает

1. Команда читает все job задачи.
2. Каждому job ставит указанные stage и state.
3. Запись задачи в кэше аннотаций очищается.

Подтверждение не спрашивается. Изменение можно вернуть: запустите команду снова со старыми значениями. Старые значения команда не запоминает.

Задача считается завершённой, только когда у каждого job stage `acceptance` и state `completed`. Только завершённые задачи попадают в `dataset.csv` (см. [Формат датасета](../dataset-format.md)).

### Результат

```text
Задача 456: обновлено 1 job(s) (stage=acceptance, state=completed)
Задача 'shelves-batch-07' (id=456): обновлено jobs: 1 (stage=acceptance, state=completed)
```

Вместо не указанного поля печатается `-`.

### Частые ошибки

```text
Ошибка: укажите хотя бы один --stage или --state.
```

Добавьте `--stage` или `--state`.

```text
cveta2 task status: error: argument --state: invalid choice: 'done' (choose from completed, in-progress, new, rejected)
```

Недопустимое значение. Выберите из списка в сообщении.

### Из Python

```python
cveta2.task_set_status(project, task, *, stage=None, state=None, connection=None) -> int
```

Возвращает число обновлённых job. Значения — как в CVAT: state пишется `"in progress"` с пробелом. Допустимые значения есть в `cveta2.JOB_STAGES` и `cveta2.JOB_STATES`. Без `stage` и `state` или с недопустимым значением функция поднимает `cveta2.Cveta2Error`.

```python
import cveta2

jobs = cveta2.task_set_status("Retail shelves", 456, stage="acceptance", state="completed")
print(jobs)
```

## Интерактивный и неинтерактивный режим

В терминале без `--project` команда просит выбрать проект. `drop-label` и `delete` без `--yes` спрашивают подтверждение. `--task` обязателен всегда: задачу команда не предлагает выбрать.

При `CVETA2_NO_INTERACTIVE=true` укажите `--project`, а для `drop-label` и `delete` ещё и `--yes`.

## Из Python: общее

Все функции принимают `project` и `task` как ID или имя и не задают вопросов. Как и команды, они очищают запись задачи в кэше аннотаций. Параметр `connection` описан на странице [Python API](../python-api.md).
