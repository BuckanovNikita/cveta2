# cveta2 verify

Проверяет CSV с аннотациями bbox или готовит каталог полной выгрузки к публикации в ClearML. Что делает команда, зависит от `input`:

- **файл** — проверка CSV: команда показывает отклонённые строки с причинами и по сети ничего не отправляет;
- **каталог** — подготовка каталога ([bundle preparation](../../GLOSSARY.md)): из каталога полной выгрузки ([full fetch](../../GLOSSARY.md)) команда пишет подготовленный датасет ([prepared bundle](../../GLOSSARY.md)), который затем публикует [`upload-dataset`](upload-dataset.md). Команда обращается к API классов, к ClearML и к S3.

Публикация одной выгрузки выглядит так:

```bash
cveta2 fetch -p "Retail shelves" -o out/fetch   # четыре CSV и черновик dataset.yaml
cveta2 verify out/fetch                         # пишет out/fetch-prepared/
# заполните split в out/fetch-prepared/dataset.csv, при необходимости поправьте dataset.yaml
cveta2 upload-dataset out/fetch-prepared
```

Назначение в ClearML, API классов, исключённые классы и корни изображений `verify` берёт из флагов, из черновика `dataset.yaml`, который `fetch` пишет по настройкам публикации проекта, и из родительского датасета (см. [Откуда берутся значения](#откуда-берутся-значения)).

## Примеры

Проверить `dataset.csv` по профилю `cveta2` и только напечатать итог:

```bash
cveta2 verify output/dataset.csv
```

Проверить CSV по профилю `clearml-yolo`, открыть каждое изображение и записать отчёт и очищенный CSV в новый каталог:

```bash
cveta2 verify output/train.csv --profile clearml-yolo --check-images --clean --output-dir output/verify-1
```

Подготовить каталог выгрузки по его черновику `dataset.yaml`; набор появится в `out/fetch-prepared`:

```bash
cveta2 verify out/fetch
```

Подготовить каталог без черновика и без вопросов в терминале:

```bash
cveta2 verify ~/data/fetch \
  --clearml-project "Retail/Datasets" --dataset-name retail-shelves \
  --api-url https://classes.example.com/api \
  --local-root ~/data/images --s3-root s3://my-bucket/images \
  --empty-class 10 --output-dir output/prepared-1 --non-interactive
```

Вернуть в обучение класс 12, исключённый в родительском датасете, и не готовить набор, если какие-то строки отклонены:

```bash
cveta2 verify out/fetch --include-class 12 --no-clean
```

## Синтаксис и аргументы

```text
cveta2 verify INPUT [--profile {cveta2,clearml-yolo}] [--check-images] [--image-root DIR]
              [--iou-threshold X] [--clean | --no-clean] [--output-dir DIR]
              [--clearml-project P] [--dataset-name N] [--output-uri URI] [--api-url URL]
              [--local-root DIR ...] [--s3-root URI ...] [--empty-class N ...] [--include-class N ...]
              [--non-interactive]
```

Общие аргументы:

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `input` | обязателен | CSV-файл — проверка CSV. Каталог — подготовка каталога: в нём должны быть `dataset.csv`, `obsolete.csv`, `in_progress.csv`, `deleted.csv` и, если есть, черновик `dataset.yaml`. |
| `--clean` | выкл. для файла | Подтверждение очистки ([cleanup acceptance](../../GLOSSARY.md)): разрешить убрать отклонённые строки и применить исправления. Для файла требует `--output-dir`. При подготовке каталога очистка и так включена. |
| `--no-clean` | выкл. | Только для каталога: не убирать отклонённые строки. Если очистка нужна, набор не готовится (код `1`). Нельзя вместе с `--clean`. |
| `--output-dir` | см. описание | Новый каталог, которого ещё нет. Для файла — каталог отчёта; без него отчёт не пишется. Для каталога — подготовленный датасет; без него `<input>-prepared` рядом с `input`, а если он занят — `<input>-prepared-2`, `-3` и так далее. |
| `-h`, `--help` | | Показать справку. |

Аргументы проверки CSV (при подготовке каталога `--check-images`, `--image-root` и изменённый `--iou-threshold` дают ошибку, `--profile` не используется):

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--profile` | `cveta2` | Профиль проверки ([verification profile](../../GLOSSARY.md)): `cveta2` или `clearml-yolo`. Подготовка каталога всегда проверяет по правилам `clearml-yolo`. |
| `--check-images` | выкл. | Открыть и декодировать каждое локальное изображение: проверить, что файл есть и читается, и сверить размеры. |
| `--image-root` | нет | Каталог, в котором искать изображение `image_name`, если ячейка `image_path` пустая. |
| `--iou-threshold` | `0.99` | Порог IoU для поиска почти одинаковых bbox и конфликтов классов. Число больше 0 и не больше 1. |

При проверке CSV из следующей таблицы разрешён только `--non-interactive`. Остальные флаги таблицы и `--no-clean` дают ошибку `Настройки подготовки относятся к каталогу полной выгрузки.`.

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--clearml-project` | `clearml.project` черновика | Проект ClearML. |
| `--dataset-name` | `clearml.dataset` черновика | Имя датасета в ClearML. |
| `--output-uri` | `clearml.output_uri` черновика | Куда ClearML загружает файлы версии, например `s3://my-bucket/.clearml`. Без флага и без ключа в черновике — хранилище ClearML по умолчанию. |
| `--api-url` | `api_url` черновика, затем родителя | Адрес API классов (HTTP или HTTPS, без логина и пароля в адресе). |
| `--local-root` | нет | Разрешённый локальный каталог с изображениями. Добавляется к корням черновика и родителя. Можно повторять. |
| `--s3-root` | нет | Разрешённый префикс `s3://bucket/prefix`. Добавляется к корням черновика и родителя. Можно повторять. |
| `--empty-class` | нет | Номер класса (`number` в API классов), который надо пометить как исключённый класс ([empty class](../../GLOSSARY.md)). Можно повторять. |
| `--include-class` | нет | Номер класса, который надо вернуть в обучение: снимает отметку «исключён», унаследованную от родителя или заданную в черновике. Можно повторять. Один номер в `--empty-class` и в `--include-class` — ошибка. |
| `--non-interactive` | выкл. | При подготовке каталога завершиться с ошибкой, если решения не хватает. Проверка CSV принимает флаг без сообщений. [Обработка аргументов и вывод](https://github.com/BuckanovNikita/cveta2/blob/8bf1e29ad4176e47419c87797b554315798051b3/cveta2/interfaces/commands/verification.py#L216-L254) |

## Проверка CSV

### Как это работает

1. Команда читает CSV как текст в UTF-8. Значения ячеек не преобразуются. Если в заголовке есть пустые или повторяющиеся имена столбцов или в строке другое число ячеек, команда сразу завершается с кодом 2.
2. До проверки значений команда определяет локальный путь для каждой строки, если есть столбец `image_name` и имена столбцов уникальны. С `--check-images` она также пробует декодировать каждый отдельный файл один раз, пропуская строки `deleted` профиля `cveta2`. [Подготовка путей](https://github.com/BuckanovNikita/cveta2/blob/8bf1e29ad4176e47419c87797b554315798051b3/cveta2/adapters/files/media.py#L64-L136) Проверяются столбцы и значения каждой ячейки по выбранному профилю. Если нет обязательного столбца, это структурная ошибка: отклоняются все строки. Изображение, в котором хотя бы одна ячейка не прошла проверку, сразу исключается из следующих шагов (в `clearml-yolo` — кроме `negative_coordinate`), поэтому другие его проблемы (например, `out_of_bounds`) не попадают в отчёт: остальные строки получают код `image_quarantined`.
3. Строки группируются по изображению. В профиле `cveta2` группа — это пара `image_name` и `task_id`, в профиле `clearml-yolo` — только `image_name`.
4. Проверяется согласованность внутри группы: пути, split и вид записей. Для групп, дошедших до этой проверки, ошибки `invalid_local_path` и `path_name_mismatch` попадают в отчёт и без `--check-images`.
5. С `--check-images` учитываются результаты чтения файлов. Путь берётся из `image_path`; если ячейка пустая, а задан `--image-root`, — из `--image-root`/`image_name`. Относительный путь считается от каталога, где лежит CSV. Адреса вида `s3://…` не читаются.
6. Проверяются согласованность размеров и границы bbox. В профиле `clearml-yolo` bbox, который выходит за край меньше чем на 10 пикселей, обрезается по краю изображения. Для обрезки нужны известные размеры и допустимый bbox после исправления. Другие ошибки изображения блокируют обрезку, кроме `out_of_bounds` и `negative_coordinate`. [Проверка и обрезка bbox](https://github.com/BuckanovNikita/cveta2/blob/8bf1e29ad4176e47419c87797b554315798051b3/cveta2/domain/verification/validation.py#L197-L369) Затем в `clearml-yolo` ищутся конфликты классов (`class_conflict`).
7. Если у изображения отклонена хотя бы одна строка, отклоняются все строки этого изображения (код `image_quarantined`).
8. Среди оставшихся строк ищутся полные дубликаты строк и почти одинаковые bbox (IoU не меньше `--iou-threshold`). Отклоняется только более поздняя строка; остальные строки изображения остаются.
9. С `--output-dir` команда сначала записывает файлы отчёта. После успешной записи или при выводе без каталога печатает итог и найденные проблемы. [Чтение CSV и запись отчёта](https://github.com/BuckanovNikita/cveta2/blob/8bf1e29ad4176e47419c87797b554315798051b3/cveta2/application/use_cases/verify.py#L19-L57) · [Обработка аргументов и вывод](https://github.com/BuckanovNikita/cveta2/blob/8bf1e29ad4176e47419c87797b554315798051b3/cveta2/interfaces/commands/verification.py#L216-L254)

Исходный CSV команда не меняет.

### Профили

| | `cveta2` | `clearml-yolo` |
|---|---|---|
| Для чего | CSV, который пишет cveta2 (`fetch`, `fetch-task`, `merge`) | CSV для обучения |
| Обязательные столбцы | `image_name`, `image_width`, `image_height`, `instance_shape`, `instance_label`, `bbox_x_tl`, `bbox_y_tl`, `bbox_x_br`, `bbox_y_br` | `image_name`, `image_path`, `instance_label`, `bbox_x_tl`, `bbox_y_tl`, `bbox_x_br`, `bbox_y_br`, `split` |
| Какие столбцы проверяются | все известные столбцы cveta2 | только обязательные и `image_width`, `image_height`, `width`, `height`; остальные столбцы переносятся без проверки |
| Пустой `split` | разрешён | запрещён |
| Строка без bbox | `instance_shape` = `none` или `deleted`, метка и координаты пустые | пустые метка и все четыре координаты |
| Минимальный bbox | ширина и высота больше 0 | ширина и высота больше 2 пикселей, площадь больше 2 |
| Выход bbox за край изображения | строка отклоняется | обрезка, если на каждой стороне меньше 10 пикселей |
| Конфликт классов | не проверяется | проверяется |
| Почти одинаковые bbox | сравниваются все bbox изображения, метка не учитывается | сравниваются bbox одного класса |

Столбцы описаны на странице [Формат данных](../dataset-format.md#столбцы-csv).

### Правила

Строка с любой из этих проблем попадает в отклонённые строки ([broken rows](../../GLOSSARY.md)). В столбце «Исправление» указано, что `--clean` может исправить вместо отклонения.

Значения ячеек:

| Код | Что отклоняется | Исправление |
|---|---|---|
| `missing_column` | Нет обязательного столбца профиля. Структурная ошибка: отклоняются все строки. | нет, `--clean` невозможен |
| `invalid_header` | У DataFrame повторяющиеся имена столбцов, пустые строки или имена другого типа. При чтении CSV некорректный заголовок отклоняется ещё до валидатора. [Проверка заголовка и изображений](https://github.com/BuckanovNikita/cveta2/blob/8bf1e29ad4176e47419c87797b554315798051b3/cveta2/domain/verification/validation.py#L475-L556) | нет |
| `invalid_text` | Непустое значение текстового поля имеет другой тип (например, в DataFrame). [Правила столбцов](https://github.com/BuckanovNikita/cveta2/blob/8bf1e29ad4176e47419c87797b554315798051b3/cveta2/domain/verification/schema.py#L270-L285) | нет |
| `invalid_image_name` | Пустое `image_name`, `.` или `..`, или имя с `/` или `\`. | нет |
| `invalid_image_path` | Пустой `image_path` (только `clearml-yolo`). | нет |
| `invalid_shape` | `instance_shape` не `box`, `none` или `deleted` (`cveta2`). | нет |
| `invalid_label` | У bbox пустая метка (label). В `cveta2` метка должна быть текстом; в `clearml-yolo` допустима и числовая метка. | нет |
| `missing_bbox` | У bbox заполнены не все четыре координаты. | нет |
| `invalid_coordinate` | Координата не конечное число. | нет |
| `negative_coordinate` | Отрицательная координата. | в `clearml-yolo` — обрезка до 0 при известных размерах, выходе меньше 10 пикселей по каждой стороне и допустимой геометрии после обрезки |
| `invalid_box_area` | Ширина или высота bbox не больше 0 (`cveta2`) или не больше 2 пикселей, либо площадь не больше 2 (`clearml-yolo`). | нет |
| `invalid_negative` | Строка без bbox (`none`, `deleted` или пустая метка) содержит метку или координаты. | нет |
| `invalid_dimension` | `image_width`, `image_height`, `width`, `height` — не положительное целое. Для строк `deleted` в `cveta2` разрешён 0. | нет |
| `invalid_integer` | `task_id`, `frame_id`, `annotation_id` — не целое число от 0; `z_order` — не целое. | нет |
| `invalid_boolean` | `occluded`, `task_completed` — не `true`/`false` (в любом регистре, например `True`) и не число 0 или 1 (`1.0` тоже подходит). | нет |
| `invalid_rotation` | `rotation` вне диапазона от 0 до 360. | нет |
| `invalid_confidence` | `confidence` вне диапазона от 0 до 1. | нет |
| `invalid_attributes` | `attributes` — не JSON-объект со строковыми ключами и значениями. | нет |
| `invalid_split` | `split` не `train`, `val` или `test`. Пустое значение запрещено в `clearml-yolo`. | нет |
| `invalid_job_stage` | `job_stage` не `annotation`, `validation` или `acceptance`. | нет |
| `invalid_job_state` | `job_state` не `new`, `in progress`, `completed` или `rejected`. | нет |
| `invalid_issue_state` | `issue_state` не `new` и не список `open`/`resolved`, разделённый ` \| `. | нет |

Согласованность изображения:

| Код | Что отклоняется | Исправление |
|---|---|---|
| `mixed_image_kinds` | В одном изображении смешаны bbox, строки без bbox и строки `deleted`. | нет |
| `path_conflict` | У одного изображения разные пути, или один путь у разных `image_name`. | нет |
| `split_conflict` | Одно изображение в разных split. | нет |
| `invalid_local_path` | `image_path` — удалённый адрес (например, `s3://…`) или путь нельзя разобрать. | нет |
| `path_name_mismatch` | Имя файла в `image_path` не совпадает с `image_name`. | нет |
| `dimension_conflict` | Строки одного изображения указывают разные размеры, или `image_width`/`image_height` не совпадают с `width`/`height`. | нет |
| `image_dimension_mismatch` | Размеры в CSV не совпадают с размерами файла (только с `--check-images`). | нет |
| `media_uninspected` | Запрошена проверка изображений, но валидатору не передан результат осмотра строки. [Проверка заголовка и изображений](https://github.com/BuckanovNikita/cveta2/blob/8bf1e29ad4176e47419c87797b554315798051b3/cveta2/domain/verification/validation.py#L475-L556) | нет |
| `media_missing` | Файла изображения нет (только с `--check-images`). | нет |
| `media_unreadable` | Файл не декодируется или у строки нет локального пути (только с `--check-images`). | нет |
| `out_of_bounds` | bbox выходит за границы изображения. Размер берётся из файла (с `--check-images`) или из столбцов размеров. | в `clearml-yolo` — обрезка по краю, если на каждой стороне выход меньше 10 пикселей и после обрезки bbox не меньше минимального |
| `image_quarantined` | Остальные строки изображения, в котором отклонена хотя бы одна строка. | нет |

Дубликаты и пересечения (проверяются после отклонения изображений):

| Код | Что отклоняется | Исправление |
|---|---|---|
| `class_conflict` | Два bbox разных классов с IoU не меньше `--iou-threshold` (только `clearml-yolo`). Отклоняются оба, а с ними всё изображение (`image_quarantined`). | нет |
| `duplicate_row` | Строка, полностью совпадающая с более ранней; отклоняется только поздняя. В `clearml-yolo` сравниваются только обязательные столбцы профиля. | нет |
| `high_iou` | bbox с IoU не меньше `--iou-threshold` относительно более раннего bbox того же изображения; отклоняется только поздний. | нет |

Предупреждения строку не отклоняют: `unknown_columns` (лишние столбцы в профиле `cveta2`, сохраняются без проверки), `unscoped_task` (у одного изображения часть строк с `task_id`, часть без), `bounds_unchecked` (размер изображения неизвестен, правая и нижняя граница не проверены), `rotation_ignored` (у bbox есть поворот, IoU считается по координатам без поворота), `empty_dataset` (в CSV нет строк), `exact_comparison_unavailable` (значение не удалось сравнить для поиска полного дубликата). [Сравнение строк](https://github.com/BuckanovNikita/cveta2/blob/8bf1e29ad4176e47419c87797b554315798051b3/cveta2/domain/verification/geometry.py#L180-L205)

### Что делает --clean

Без `--clean` любая отклонённая строка или предлагаемое исправление означает, что CSV не готов: код завершения 1.

С `--clean` и `--output-dir` команда:

- пишет `clean.csv` — очищенный CSV ([clean CSV](../../GLOSSARY.md)): все неотклонённые строки в исходном порядке и со всеми столбцами, с применёнными исправлениями (обрезка bbox);
- завершается с кодом 0, даже если строки были отклонены.

Структурную ошибку (например, нет обязательного столбца) очистить нельзя: команда завершается с кодом 2 и не создаёт каталог.

Пример исправления в выводе:

```text
bbox_clipped строка 8: Clipped image-boundary overflow below 10 px per edge; before ('103.17', '18.20', '645.0', '315.36'); after ('103.17', '18.20', '640', '315.36').
```

### Результат

Если запись отчёта завершается ошибкой, команда возвращает код 2 без итоговой сводки. При успехе печатаются итог и по строке на каждую проблему. Нумерация строк начинается с 0 без заголовка.

```text
Проверка: 31 строк; допустимых 16, отклонённых 15.
out_of_bounds строка 10: Box extends outside image bounds 0..640 x 0..428; image/task is rejected.
image_quarantined строка 11: Another malformed record quarantined this entire image/task.
duplicate_row строка 30: Later full-row duplicate.
```

С `--output-dir` команда создаёт каталог и пишет в него:

| Файл | Когда | Содержимое |
|---|---|---|
| `report.json` | всегда | Отчёт проверки ([verification report](../../GLOSSARY.md)): профиль, `is_valid`, `requires_cleanup`, `structural_errors`, счётчики строк и изображений, номера допустимых и отклонённых строк, выполненные и пропущенные проверки, список всех проблем. В `metadata_columns` указаны фактические имена трёх диагностических столбцов `broken.csv`; при совпадении с входным именем добавляется `_`. [Ключи отчёта CSV](https://github.com/BuckanovNikita/cveta2/blob/8bf1e29ad4176e47419c87797b554315798051b3/cveta2/adapters/files/verification.py#L51-L84) |
| `broken.csv` | всегда | Отклонённые строки без изменений и три столбца: `__validator_row_position` (номер строки), `__validator_reason_codes` и `__validator_reasons` (JSON-списки кодов и сообщений). |
| `clean.csv` | только с `--clean` | Очищенный CSV. |

Каталог `--output-dir` не должен существовать и не должен совпадать с каталогом, где лежит входной CSV.

### Коды завершения

| Код | Когда |
|---|---|
| 0 | Нет отклонённых строк и исправлений, или задан `--clean` и нет структурных ошибок. |
| 1 | Есть отклонённые строки или исправления без `--clean`; структурная ошибка (нет обязательного столбца); проверка прервана (Ctrl+C). |
| 2 | Ошибка аргументов (в том числе флаг подготовки каталога с файлом), нет такого файла или каталога, CSV не читается, каталог `--output-dir` уже есть или совпадает с каталогом CSV, `--clean` при структурной ошибке. |

### Частые ошибки

```text
Ошибка проверки: Для --clean требуется --output-dir.
```

Добавьте `--output-dir` с новым каталогом.

```text
Ошибка проверки: Нет такого файла или каталога: run2/nope
```

Пути `input` нет. Проверьте путь к CSV-файлу или каталогу выгрузки; с флагами подготовки команда печатает эту же ошибку.

```text
Ошибка проверки: Настройки подготовки относятся к каталогу полной выгрузки.
```

Флаги подготовки (`--clearml-project`, `--dataset-name`, `--output-uri`, `--api-url`, `--local-root`, `--s3-root`, `--empty-class`, `--include-class`, `--no-clean`) переданы вместе с CSV-файлом. Уберите их или передайте каталог выгрузки, а не файл.

```text
Ошибка проверки: Cannot write verification output: [Errno 17] File exists: 'output/verify-1'
```

Каталог отчёта уже есть. Укажите новый каталог: команда не перезаписывает старые отчёты.

```text
Ошибка проверки: Cannot write verification output: Reports require a new directory separate from the input.
```

`--output-dir` совпадает с каталогом входного CSV. Укажите другой каталог.

```text
Ошибка проверки: Cannot load verification input output/train.csv: CSV record 2 has 1 cells; expected 2.
```

В строке файла другое число ячеек, чем в заголовке. Исправьте CSV.

```text
Ошибка проверки: Cannot write verification output: Structural errors cannot be cleaned away.
```

В CSV нет обязательного столбца, а вы указали `--clean`. Добавьте столбец; `--clean` его не заменит.

```text
invalid_split строка 0: Expected train, val or test (an empty split is allowed only in cveta2): split.
```

Профиль `clearml-yolo` требует split у каждой строки. `fetch` оставляет `split` пустым: заполните его перед проверкой. См. [split](../dataset-format.md#split).

## Подготовка каталога

### Что нужно

- Каталог полной выгрузки (`cveta2 fetch -p <проект> -o <каталог>`) со всеми четырьмя файлами. В `dataset.csv` у каждой строки `image_path` — абсолютный локальный путь к существующему файлу изображения. `split` может быть пустым: его можно заполнить после подготовки. Формат файлов — на странице [Формат данных](../dataset-format.md#файлы-полной-выгрузки).
- Назначение в ClearML и адрес API классов — реестра классов ([class registry](../../GLOSSARY.md)): в черновике `dataset.yaml`, во флагах или (только API классов) в родительском датасете.
- Подключение к ClearML. Проверить его можно командой [`cveta2 doctor`](doctor.md). Если S3 работает на своём адресе (например, MinIO), ClearML получает этот адрес отдельно: переменной `AWS_ENDPOINT_URL_S3` или записью `credentials` в `clearml.conf`.

### Откуда берутся значения

Для каждого значения берётся первый найденный источник слева направо. Исключённые классы и корни изображений складываются из нескольких источников, правила — ниже.

| Значение | 1. Флаг | 2. Черновик в каталоге выгрузки | 3. Родительский датасет | 4. Иначе |
|---|---|---|---|---|
| Проект ClearML | `--clearml-project` | `clearml.project` | — | вопрос или недостающее решение |
| Имя датасета | `--dataset-name` | `clearml.dataset` | — | вопрос или недостающее решение |
| Хранилище файлов версии | `--output-uri` | `clearml.output_uri` | — | хранилище ClearML по умолчанию |
| API классов | `--api-url` | `api_url` | `api_url` родителя | вопрос или недостающее решение |
| Исключённые классы | `--empty-class` добавляет, `--include-class` убирает | `empty_classes` добавляет | отметки `empty` родителя сохраняются | класс не исключён |
| Корни изображений | `--local-root`, `--s3-root` | `images` | корни родителя | нет |

`verify` читает черновик `dataset.yaml` из каталога выгрузки, а не конфигурацию: каталог выгрузки самодостаточен, и черновик можно поправить перед подготовкой. Ключи черновика описаны в [fetch](fetch.md#черновик-datasetyaml). Черновик, который не проходит строгую проверку, — ошибка с именем файла и поля. Без черновика значения берутся из флагов, из родителя или из ответов на вопросы.

**Исключённые классы.** Класс, исключённый в родительском датасете, остаётся исключённым. `empty_classes` черновика и `--empty-class` добавляют исключения. По умолчанию ничего не возвращается в обучение: чтобы вернуть класс, передайте `--include-class <номер>`, он снимает отметку родителя и черновика. Один номер в `--empty-class` и в `--include-class` — ошибка. Номер, которого нет в реестре классов, — тоже ошибка. Каждый класс, у которого отметка отличается от родительской, печатается (`Класс 10 umbrella исключён`, `Класс 12 cup возвращён`) и попадает в `class_marks` в `report.json`.

**Корни изображений.** Корни — объединение флагов, черновика и родителя. Локальный корень родителя, которого нет на этом компьютере, не переносится в новый `dataset.yaml`: команда печатает `Корень родителя <каталог> не найден на этой машине и не перенесён`, а `report.json` перечисляет такие корни в `dropped_local_roots`. Локальные корни у каждого, кто публикует, свои: свой каталог изображений вы добавляете черновиком (`fetch` пишет туда кэш изображений) или флагом `--local-root`.

### Как это работает

1. Команда проверяет аргументы: `--check-images`, `--image-root` и изменённый `--iou-threshold` запрещены (изображения проверяются всегда), один номер в `--empty-class` и в `--include-class` запрещён.
2. Читает четыре файла выгрузки и черновик `dataset.yaml`, если он есть.
3. Проверяет, что каждый файл из `image_path` существует. Если каких-то файлов нет, команда останавливается с кодом 2 и печатает их список.
4. Определяет проект и имя датасета ClearML (см. [таблицу](#откуда-берутся-значения)). Если их нет, спрашивает в терминале.
5. Ищет в ClearML родительский датасет ([parent dataset](../../GLOSSARY.md)): последнюю завершённую (finalized) неархивную версию с этим именем ровно в этом проекте (без подпроектов). Если она есть, скачивает её `dataset.yaml`. Родитель без `dataset.yaml` останавливает команду. Родитель, у которого в `dataset.yaml` есть блок `managed`, тоже: этот датасет ClearML принадлежит управляемому датасету ([managed dataset](../../GLOSSARY.md)). Пока в проекте ClearML нет ни одного датасета, ClearML SDK печатает предупреждение `No projects were found with name(s): ...`. Это не ошибка: проект появится при первой публикации.
6. Заполняет пустые ячейки `split` из `dataset.csv` родителя (см. [Split](#split)).
7. Запрашивает список классов из API (GET без авторизации, тайм-аут 30 секунд). Классы сопоставляются с классами родителя по номеру класса ([class identity](../../GLOSSARY.md)) — полю `number` в API, в `dataset.yaml` это `prod_id`:
   - класс с новым номером — добавленный; без родителя добавленные — все классы;
   - класс с прежним номером и новым именем — переименованный; старое имя сохраняется как псевдоним (`alt_names`), а метки со старым именем в CSV заменяются на каноническое имя класса ([canonical class name](../../GLOSSARY.md));
   - если номер класса из родителя пропал из API, команда останавливается.

   Команда ничего не спрашивает о классах. Если родитель есть, изменения печатаются по одной строке (`Класс добавлен: 14 cup`, `Класс переименован: 3 dog → canine`). Без родителя печатается одна строка: `Родительской версии нет: 42 классов из API, исключено 2`. В обоих случаях изменения попадают в `class_changes` в `report.json`. Затем применяются отметки «исключён» (см. [Исключённые классы](#откуда-берутся-значения)).
8. Собирает корни изображений. Каждый `image_path` должен лежать внутри одного из локальных корней. Если какие-то файлы вне корней, команда показывает их родительские каталоги и спрашивает, разрешить ли их. Каждое значение `s3_image_path` должно попадать ровно в один корень S3. Каждый корень S3 должен быть доступен для чтения списка объектов (это проверяется через ClearML SDK), а непустой префикс должен существовать. Пустой или относительный `image_path` останавливает команду с кодом 2.
9. Проверяет `dataset.csv` по правилам профиля `clearml-yolo` с открытием каждого изображения (см. [Правила](#правила)). Пустой `split` при подготовке разрешён, а значение не из `train`, `val`, `test` отклоняет строку (`invalid_split`). Дополнительно:

   | Код | Что отклоняется | Исправление |
   |---|---|---|
   | `unknown_class` | Метки нет среди имён и псевдонимов классов API. | нет |
   | `empty_class` | Класс помечен как исключённый. | нет |
   | `class_canonicalized` | Метка — старое имя класса. | замена на каноническое имя |
   | `training_image_format` | Расширение или формат файла не из списка: `avif`, `bmp`, `jp2`, `jpeg`, `jpg`, `mpo`, `png`, `tif`, `tiff`, `webp`. | нет |
   | `training_image_size` | Сторона изображения меньше 10 пикселей. | нет |
   | `image_quarantined` | Остальные строки изображения с отклонённой строкой. | нет |

10. Из четырёх файлов выводит список задач датасета ([task manifest](../../GLOSSARY.md), `tasks.yaml`): задачи, строки которых остались в очищенном `dataset.csv`, и завершённые задачи ([completed task](../../GLOSSARY.md)), все изображения которых заменены более новыми результатами.
11. Проверяет блокирующие условия (см. [Блокирующие условия](#блокирующие-условия)) и условия split, которые потребует `upload-dataset` (`pending`).
12. Пишет каталог во временный каталог рядом и переносит его на место одним переименованием: прерванная запись не оставляет ничего. Команда ничего не создаёт в ClearML и ничего не меняет в S3 и CVAT.

Состав каталога описан на странице [Формат данных](../dataset-format.md#подготовленный-датасет).

### Очистка и каталог результата

Очистка при подготовке включена: отклонённые строки не попадают в `dataset.csv` (по правилам проверки ошибка в изображении отклоняет все его строки, а у дубликатов отклоняется только более поздняя строка), исправления (обрезка bbox, замена старых имён классов) применяются. Строки всех изображений, в которых отклонена хотя бы одна строка, записываются в `broken-images.csv` такими, какими они стали после заполнения split из родителя, но до исправлений; команда печатает, сколько там строк и изображений, и путь к файлу. Код завершения — 0, сколько бы строк ни было отклонено. С `--no-clean` любая отклонённая строка или исправление делает набор неготовым. `--clean` принимается, но ничего не меняет.

Каталог результата — `--output-dir`, а без него `<input>-prepared` рядом с `input`, затем `<input>-prepared-2`, `-3` и так далее: первый ещё не занятый. Указанный `--output-dir` не должен существовать, поэтому повторный запуск никогда не перезаписывает ваши правки. Каталог результата не должен лежать внутри каталога `input`. Команда печатает путь к нему: каталог по умолчанию — абсолютным путём, `--output-dir` — как он указан.

### Split

Split — ваш: cveta2 никогда не назначает его сам. `verify` скачивает `dataset.csv` родительского датасета и у изображений, которые есть в родителе (по `image_name`), заполняет пустые ячейки `split` опубликованным split ([stable split](../../GLOSSARY.md)). Значение, которое вы уже написали, сохраняется. Изображение, у которого в другой строке уже стоит другой split, не заполняется. Команда печатает `split заполнен из родителя у <N> изображений`, а `report.json` хранит это число в `split_prefilled`.

Оставшиеся пустые `split` разрешены: они попадают в `pending` (`заполните split у <N> изображений в <каталог>/dataset.csv`), и их заполняете вы в подготовленном `dataset.csv`. Если split заполнен у всех строк, в `pending` попадают пустые `train` или `val` и отсутствие bbox в `train` (`в train нет изображений`, `в val нет изображений`, `в train нет ни одного bbox`). Если изображение уже опубликовано в родителе, а в `dataset.csv` у него другой split (вы вписали его сами в каталоге выгрузки), в `pending` попадает ещё одна строка: `у <N> изображений split отличается от опубликованного в родителе <ID>: upload-dataset откажет без --force-resplit`. Она печатается вместе с остальными условиями. `upload-dataset` потом требует split у каждой строки и отказывается публиковать изображение родителя с другим split, если не задан `--force-resplit` (см. [upload-dataset](upload-dataset.md)).

### Блокирующие условия

Блокирующее условие ([blocker](../../GLOSSARY.md)) не даёт записать `dataset.csv`, `dataset.yaml` и `tasks.yaml`:

| Условие | Сообщение |
|---|---|
| структурная ошибка в CSV | `Input CSV has structural validation errors.` |
| после отклонения не осталось изображений | `No valid images remain for upload.` |
| нужна очистка, а задан `--no-clean` | `Нужна очистка: отклонено <N> строк; запустите verify без --no-clean или исправьте исходные данные.` |
| у неисключённого класса нет ни одного bbox среди строк, оставшихся после очистки (в любом split) | `Нет ни одного bbox классов <имена>: исключите их (--empty-class N или empty_classes в dataset.yaml выгрузки) или выгрузите данные с ними.` |
| ошибка построения списка задач по таблицам выгрузки и очищенным строкам | Текст ошибки, например `Clean task/image pairs must originate in dataset.csv`. [Подготовка и построение списка задач](https://github.com/BuckanovNikita/cveta2/blob/8bf1e29ad4176e47419c87797b554315798051b3/cveta2/application/use_cases/dataset_bundle.py#L250-L284) |

У класса без bbox три выхода: `--empty-class <номер>`, номер в `empty_classes` черновика или выгрузка данных, где этот класс есть.

Пустой или относительный `image_path` и отсутствующий файл изображения — не блокирующие условия, а ошибки: команда завершается с кодом 2 и ничего не пишет.

### Результат

Всегда пишутся `sources.tar.gz` (архив четырёх файлов), `broken-images.csv` (все строки изображений, у которых отклонена хотя бы одна строка, после заполнения пустых split из родителя) и `report.json` (отчёт проверки плюс итог подготовки). Если блокирующих условий нет, добавляются `dataset.csv`, `dataset.yaml` и `tasks.yaml`.

В `report.json` подготовки убирается `metadata_columns`. Добавляются `blockers`, `ready` и перечисленные ниже поля. [Отчёт подготовки](https://github.com/BuckanovNikita/cveta2/blob/8bf1e29ad4176e47419c87797b554315798051b3/cveta2/adapters/files/bundle.py#L204-L220)

- `pending` — только условия split, которые `upload-dataset` потребует, но которые пока не выполнены;
- `parent` — ID и версия родителя, которого видела подготовка, или `null`;
- `destination` — проект и имя датасета ClearML;
- `class_changes` и `class_marks` — изменения классов и отметок «исключён»;
- `dropped_local_roots` — локальные корни родителя, которые не перенесены;
- `split_prefilled` — сколько изображений получили split родителя.

Все ключи — в [report.json](../dataset-format.md#reportjson).

Вывод готовой подготовки:

```text
Проверка: 30 строк; допустимых 28, отклонённых 2.
empty_class строка 13: Class is marked empty: 'umbrella'
image_quarantined строка 14: Another rejected record quarantined this image.
split заполнен из родителя у 25 изображений
Класс добавлен: 14 cup
Класс 10 umbrella исключён
В broken-images.csv записано 2 строк 1 изображений с отклонёнными строками: /home/user/out/fetch-prepared/broken-images.csv
Набор подготовлен: /home/user/out/fetch-prepared
Перед публикацией: заполните split у 120 изображений в /home/user/out/fetch-prepared/dataset.csv
Затем: cveta2 upload-dataset /home/user/out/fetch-prepared
```

Строки `Перед публикацией:` печатаются по одной на каждое условие из `pending`; если условий нет, их нет. Если набор не подготовлен, команда печатает блокирующие условия и вместо последних строк:

```text
Набор не подготовлен; отчёт: /home/user/out/fetch-prepared/report.json
```

Файлы подготовленного каталога можно править: `upload-dataset` проверяет их такими, какие они есть (см. [upload-dataset](upload-dataset.md#что-можно-править)).

### Коды завершения

| Код | Когда |
|---|---|
| 0 | Набор записан, сколько бы строк ни убрала очистка. Условия `pending` могут оставаться. |
| 1 | Набор не подготовлен из-за блокирующего условия (каталог с `sources.tar.gz`, `broken-images.csv` и `report.json` всё равно создан); вы ответили «нет» или пустой строкой на вопрос; команда прервана. |
| 2 | Ошибка аргументов; не хватает решения без терминала; нет файла изображения, пустой или относительный `image_path`; файлы вне корней изображений; ошибка API классов, ClearML или S3; родитель управляемого датасета; каталог результата уже есть. Ничего не записано. |

### Частые ошибки

```text
Ошибка проверки: Параметры --check-images, --image-root и изменённый --iou-threshold относятся к проверке CSV; подготовка каталога всегда проверяет изображения.
```

Уберите эти флаги: при подготовке изображения проверяются всегда.

```text
Ошибка проверки: Класс 12 указан и в --empty-class, и в --include-class.
```

Оставьте номер только в одном из флагов.

```text
Ошибка проверки: Укажите проект ClearML.
Укажите имя датасета ClearML.
```

Назначения нет ни во флагах, ни в черновике, а спросить нельзя (нет терминала или задан `--non-interactive`). Опишите настройки публикации проекта (`cveta2 setup --global --project … --clearml-project … --dataset-name … --api-url …`, см. [setup](setup.md)) и выгрузите заново, впишите `clearml.project` и `clearml.dataset` в черновик или передайте `--clearml-project` и `--dataset-name`.

```text
Ошибка проверки: Нет файлов изображений из image_path (1):
  /home/user/data/images/shelf_0009.jpg
Скачайте изображения (cveta2 s3-sync) или выполните cveta2 fetch заново.
```

Файлов изображений нет на диске. Скачайте их и подготовьте заново.

```text
Ошибка проверки: Upload image_path must be an absolute local path: ''
```

У строки пустой или относительный `image_path`. Скачайте изображения ([`cveta2 s3-sync`](s3-sync.md) или `fetch` без `--no-images`) или впишите абсолютный путь.

```text
Ошибка проверки: Укажите разрешённые каталоги изображений:
/home/user/data/images/shelf_0009.jpg
```

Файлы лежат вне разрешённых локальных корней. Добавьте `--local-root` с каталогом, в котором они лежат, или впишите его в `images.local_root` черновика.

```text
Ошибка проверки: S3 image path is outside approved S3 roots: 'shelf_0009.jpg'
```

В `dataset.csv` заполнен `s3_image_path`, а подходящего корня S3 нет. Добавьте `--s3-root s3://my-bucket/images` с бакетом и префиксом, где лежат изображения.

```text
Ошибка проверки: Номера классов [99] нет в реестре классов.
```

Номер из `--empty-class`, `--include-class` или `empty_classes` черновика не найден в API классов. Исправьте номер.

```text
Ошибка проверки: Родитель <id> принадлежит управляемому датасету; выберите другое имя или используйте cveta2 dataset.
```

Этот датасет ClearML публикуется командами [`cveta2 dataset`](dataset.md). Выберите другое имя датасета или работайте через управляемый датасет.

```text
Ошибка проверки: Родитель <id> не содержит dataset.yaml. Выберите новое имя датасета.
```

В ClearML уже есть датасет с этим именем, но он создан не cveta2. Укажите другое имя датасета.

```text
Ошибка проверки: Preparation directory already exists: /home/user/out/prepared-1
Ошибка проверки: Preparation must be outside the source directory.
```

Каталог `--output-dir` уже есть или лежит внутри каталога `input`. Укажите новый каталог вне выгрузки или не указывайте `--output-dir`. Эта проверка идёт в самом конце, после запросов к ClearML и API классов.

```text
Нет ни одного bbox классов bowl: исключите их (--empty-class N или empty_classes в dataset.yaml выгрузки) или выгрузите данные с ними.
```

Это блокирующее условие. Исключите класс или выгрузите данные, где он есть, и подготовьте заново.

```text
Ошибка проверки: Class API returned HTTP 404; check the public endpoint
Ошибка проверки: Class API must return a JSON list of valid class definitions
Ошибка проверки: Class API must return a JSON list of valid class definitions: record 2: name: Field required
```

Проверьте адрес API классов. API должен отдавать JSON-список объектов с полями `id`, `number`, `name` и `threshold`. Флаги `techClass`, `isPeriodical` и `isCritical` необязательны: отсутствующий флаг читается как `false`, а указанный должен быть JSON-значением `true` или `false`. Если запись не подходит, ошибка называет её номер в списке (с нуля), поле и причину, но не значение.

## Интерактивный и неинтерактивный режим

Проверка CSV ничего не спрашивает.

Подготовка каталога задаёт вопросы, только если стандартный ввод — терминал, не задан `--non-interactive` и `CVETA2_NO_INTERACTIVE` не равно `true`. О классах она не спрашивает никогда:

| Чего не хватает | Вопрос | Флаг или ключ черновика для неинтерактивного режима |
|---|---|---|
| проекта ClearML | `Укажите проект ClearML.` (ввод текста) | `--clearml-project`, `clearml.project` |
| имени датасета | `Укажите имя датасета ClearML.` (ввод текста) | `--dataset-name`, `clearml.dataset` |
| адреса API классов | `Укажите URL API классов.` (ввод текста) | `--api-url`, `api_url` |
| корней для файлов | `Разрешить каталоги:` и список родительских каталогов файлов (да/нет; «нет» отменяет подготовку) | `--local-root`, `images.local_root` |

Пустой ответ на текстовый вопрос отменяет подготовку с кодом 1 и сообщением `Проверка отменена.`.

Без терминала недостающее решение даёт ошибку с кодом 2: команда печатает `Ошибка проверки:` и тексты вопросов. Решения проверяются по очереди (проект и имя датасета, адрес API, корни изображений), и команда останавливается на первом шаге, где чего-то не хватает. Поэтому после исправления может появиться следующий вопрос. В отличие от других команд здесь не печатается сообщение `Interactive prompt required…` из [неинтерактивного режима](../configuration.md#неинтерактивный-режим).

## Из Python

Функции доступны как `cveta2.verify`, `cveta2.verify_dataframe` и `cveta2.prepare_dataset`. Они ничего не спрашивают в терминале.

```python
def verify(
    path: str | Path,
    *,
    profile: Profile = "cveta2",
    options: ValidationOptions | None = None,
    output_dir: str | Path | None = None,
    clean: bool = False,
) -> ValidationResult

def verify_dataframe(
    frame: pd.DataFrame,
    *,
    profile: Profile = "cveta2",
    options: ValidationOptions | None = None,
) -> ValidationResult

def prepare_dataset(
    source: str | Path,
    *,
    output_dir: str | Path | None = None,
    options: PrepareOptions | None = None,
) -> PreparedDataset
```

- `ValidationOptions(iou_threshold=0.99, check_images=False, image_root=None, base_dir=None, emit_warnings=True)`. `base_dir` — каталог для относительных путей (по умолчанию каталог CSV). С `emit_warnings=True` предупреждения выдаются через модуль `warnings` (класс `cveta2.DatasetWarning`).
- `ValidationResult` содержит `clean` и `broken` (DataFrame), `issues` (список `Issue` с полями `code`, `message`, `severity`, `row_position`, `columns`, `related_rows`, `iou`), свойства `is_valid` и `requires_cleanup`, метод `reasons_for(row_position)`. `verify_dataframe` ничего не пишет на диск.
- `verify` бросает `cveta2.DatasetInputError`, если CSV не читается или каталог отчёта нельзя создать.
- `prepare_dataset(source)` готовит набор из каталога `fetch`, как `cveta2 verify <каталог>`. Без `output_dir` набор пишется рядом с `source`: в `<source>-prepared`, а если он занят — в `<source>-prepared-2`, `-3` и так далее. Указанный `output_dir` не должен существовать. `options=None` означает `PrepareOptions()`.
- `PrepareOptions(project=None, dataset_name=None, output_uri=None, api_url=None, local_roots=(), s3_roots=(), class_empty={}, clean=True)`. Незаданное значение берётся из черновика `dataset.yaml` в `source`, а `api_url` — затем из родительского датасета. Корни изображений (`local_roots`, `s3_roots`) складываются с корнями черновика и родителя.
  - `project` и `dataset_name` — проект и имя датасета ClearML. Оба необязательны, если они есть в черновике (`clearml.project`, `clearml.dataset`).
  - `output_uri` — куда ClearML загружает файлы датасета; без него — из черновика (`clearml.output_uri`), иначе хранилище ClearML по умолчанию.
  - `class_empty` — словарь «номер класса → исключён ли». `{N: True}` исключает класс. `{N: False}` возвращает класс, исключённый в родительском датасете: без этого его отметка сохраняется. Номер, которого нет в реестре классов, — ошибка.
  - `clean=True` (по умолчанию): строки, которые отклонила проверка, не попадают в набор и не мешают ему. С `clean=False` такие строки блокируют набор.
- Если не хватает решения, `prepare_dataset` бросает `cveta2.MissingDecisions` с кортежем `decisions`; у каждого решения есть `kind`, `message` и `choices`. Значения `kind`: `project`, `dataset_name`, `api_url` (URL API классов), `local_roots` (в `choices` — пути изображений вне разрешённых каталогов). Прочие ошибки — подклассы `cveta2.Cveta2Error`. Пустой или относительный `image_path` и отсутствующий файл изображения — тоже ошибка: тогда ничего не пишется.
- `PreparedDataset` содержит поля:
  - `directory`, `ready`, `validation`, `metadata`, `tasks`;
  - `parent` — родительский датасет, который видела подготовка (поля `dataset_id`, `project`, `name`, `version`), или `None`;
  - `blockers` — что не даёт записать `dataset.csv`, `dataset.yaml` и `tasks.yaml` (тогда `ready` ложно). Например, класс без единого bbox, который не исключён;
  - `pending` — что `upload-dataset` потребует, но пока не выполнено: пустой `split`, нет изображений в `train` или `val`, нет ни одного bbox в `train`, у опубликованных в родителе изображений другой split. Если `ready`, набор при этом записан;
  - `changes` — добавленные и переименованные классы реестра;
  - `mark_changes` — классы, у которых отметка «исключён» отличается от родительской;
  - `dropped_local_roots` — локальные корни родителя, которых нет на этом компьютере;
  - `split_prefilled` — сколько изображений получили `split` из `dataset.csv` родителя. Заполняются только пустые ячейки и только у изображений, в остальных строках которых `split` пуст или совпадает с опубликованным; изображение с другим значением остаётся как есть.

```python
import cveta2

result = cveta2.verify(
    "output/train.csv",
    profile="clearml-yolo",
    options=cveta2.ValidationOptions(check_images=True, emit_warnings=False),
)
print(result.is_valid, len(result.clean), len(result.broken))
for issue in result.issues:
    print(issue.code, issue.row_position, issue.message)

try:
    # Назначение, API классов и корни берутся из черновика output/fetch/dataset.yaml.
    prepared = cveta2.prepare_dataset(
        "output/fetch",  # ~ в пути не раскрывается
        options=cveta2.PrepareOptions(class_empty={10: True, 12: False}),
    )
    print(prepared.ready, prepared.directory)  # абсолютный путь к output/fetch-prepared
    for item in prepared.pending:
        print("перед публикацией:", item)
except cveta2.MissingDecisions as error:
    for decision in error.decisions:
        print(decision.kind, decision.message)
```
