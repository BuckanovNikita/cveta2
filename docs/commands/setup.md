# cveta2 setup

Записывает настройки cveta2: логин и пароль CVAT и пути кэша в личную конфигурацию ([personal configuration](../../GLOSSARY.md)), настройки проектов в общую конфигурацию ([global configuration](../../GLOSSARY.md)) или в ваши локальные переопределения ([local override](../../GLOSSARY.md)). С флагами-значениями команда ничего не спрашивает и записывает ровно эти значения, как `git config`. Без них она работает как мастер в терминале. Ключи обоих файлов описаны на странице [Конфигурация](../configuration.md).

## Примеры

Сначала личные настройки: логин, пароль (скрытый ввод в терминале) и пути кэша:

```bash
cveta2 setup --username alice --password
cveta2 setup --images-root /data/images --tasks-root /data/tasks
cveta2 setup --project "Retail shelves" --images-dir /data/retail
```

Подключить общий файл, полученный от команды (работает и без терминала):

```bash
cveta2 setup --global-config ~/team/project-config.yaml
```

Задать настройки публикации проекта для всей команды (записываются в общий файл):

```bash
cveta2 setup --global --project retail \
  --clearml-project Retail/Datasets --dataset-name retail-shelves \
  --api-url https://classes.example.com/api --empty-class 12 --empty-class 13
```

Создать новый общий файл и подключить его. Новый файл разрешает локальные переопределения:

```bash
cveta2 setup --global --global-config ~/team/project-config.yaml \
  --host https://cvat.example.com --organization my-team
```

Публиковать проект в свой датасет ClearML, не меняя общий файл (локальное переопределение):

```bash
cveta2 setup --project retail --dataset-name retail-shelves-alice
```

Удалить значения: своё переопределение, значение из общего файла, весь блок публикации:

```bash
cveta2 setup --project retail --unset dataset-name
cveta2 setup --global --project retail --unset sync-root
cveta2 setup --global --project retail --unset publication
```

Посмотреть итоговые настройки и откуда взято каждое значение:

```bash
cveta2 setup --list
cveta2 setup --list --project retail
```

Ввести логин и пароль CVAT в мастере (в терминале):

```bash
cveta2 setup
```

Перенести старую конфигурацию из одного файла в личный и общий файлы (в терминале):

```bash
cveta2 setup --migrate-config
```

## Синтаксис и аргументы

```text
cveta2 setup [--config PATH] [--global-config PATH] [--migrate-config]
             [--global] [--project PROJECT] [--list] [--unset OPTION ...] [--reset]
             [--<option> VALUE ...]
```

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--config CONFIG` | `CVETA2_CONFIG` или `~/.config/cveta2/config.yaml` | Личный файл, который команда читает и записывает. |
| `--global-config GLOBAL_CONFIG` | `CVETA2_GLOBAL_CONFIG`, затем ключ `global_config` личного файла | Без `--global`: подключить этот общий файл (и затем записать значения флагов, если они есть). С `--global`: записывать в этот файл; с `--host` и несуществующим путём — создать его. С `--migrate-config`: куда записать общий файл при переносе. |
| `--project-config PROJECT_CONFIG` | нет | Старое написание `--global-config`. Если заданы оба флага с разными путями, команда останавливается: `Заданы оба варианта: --global-config=<путь> и --project-config=<путь>, и они различаются. ...` |
| `--migrate-config` | выкл. | Перенести старую конфигурацию из одного файла в личный и общий файлы. Сочетается только с `--config` и `--global-config`. |
| `--global` | выкл. | Записывать в общий файл команды, а не в личный. |
| `--project PROJECT`, `-p PROJECT` | нет | Проект CVAT: ключ общего файла, имя проекта или ID (см. [Как выбирается проект](#как-выбирается-проект)). Нужен для `--images-dir` и всех настроек проекта. |
| `--list` | выкл. | Показать итоговую конфигурацию и источник каждого значения (см. [Просмотр настроек](#просмотр-настроек---list)). Ничего не записывает. Сочетается только с `--config`, `--global-config` и `--project`. |
| `--unset OPTION [OPTION ...]` | нет | Удалить значения из выбранного файла. `OPTION` — имя флага без `--` (`dataset-name`, `sync-root`, …) или `publication` — весь блок публикации проекта. Неизвестное имя — ошибка разбора аргументов (код 2). |
| `--reset` | выкл. | Для мастера кэша: заново предложить путь каждого проекта, не глядя на сохранённые. Не сочетается с флагами-значениями, `--unset` и `--global`. |
| `-h`, `--help` | | Показать справку. |

Флаги-значения и куда они записываются:

| Флаг | Ключ | Без `--global` | С `--global` |
|---|---|---|---|
| `--username NAME` | `cvat.username` | личный файл | ошибка |
| `--password` (без значения; скрытый ввод) | `cvat.password` | личный файл | ошибка |
| `--images-root PATH`, `--tasks-root PATH` | `cache.images_root`, `cache.tasks_root` | личный файл | ошибка |
| `--project P --images-dir PATH` | `image_cache.<имя проекта>` | личный файл | ошибка |
| `--host URL`, `--organization SLUG` | `cvat.host`, `cvat.organization` | личный файл, только если общий файл не подключён (старый формат) | общий файл |
| `--local-overrides on\|off` | `local_overrides` | ошибка | общий файл |
| `--project P --sync-root`, `--ignored-prefix`, `--task-cache-s3` | `projects.<ключ>.sync_root`, `.ignored_prefix`, `.task_cache_s3` | ошибка | общий файл |
| `--project P --clearml-project`, `--dataset-name`, `--output-uri` | `projects.<ключ>.publication.clearml.project`, `.dataset`, `.output_uri` | локальное переопределение | общий файл |
| `--project P --api-url URL` | `projects.<ключ>.publication.api_url` | локальное переопределение | общий файл |
| `--project P --empty-class N` (повторяется) | `projects.<ключ>.publication.empty_classes` | локальное переопределение | общий файл |
| `--project P --s3-root URI` (повторяется) | `projects.<ключ>.publication.s3_roots` | локальное переопределение | общий файл |

`--empty-class` и `--s3-root` можно повторять; заданный список заменяет прежний целиком: `--empty-class 5` после `[12, 13]` даёт `[5]`. `--local-overrides off` удаляет ключ из общего файла: `false` — значение по умолчанию.

Пароль никогда не передаётся в командной строке: `--password` не принимает значения и открывает скрытый ввод. Скрипты задают пароль через `CVAT_PASSWORD`.

## Как это работает

Команда выбирает режим в таком порядке:

1. `--list` — [просмотр настроек](#просмотр-настроек---list). Ничего не записывает и ничего не подключает.
2. `--migrate-config` — [перенос старой конфигурации](#перенос-старой-конфигурации---migrate-config).
3. Проверка сочетания флагов (таблица в [Частых ошибках](#частые-ошибки)). Если сочетание недопустимо, команда ничего не записывает.
4. `--global --host` и несуществующий путь общего файла — [создание общего файла](#создание-общего-файла).
5. `--global-config` без `--global` — [подключение общего файла](#подключение-общего-файла---global-config).
6. Флаги-значения или `--unset` — [запись значений](#запись-значений).
7. Иначе — [мастер настройки](#мастер-настройки-без-флагов).

### Просмотр настроек (`--list`)

`cveta2 setup --list` выводит итоговую конфигурацию — то, что увидят остальные команды, — и для каждого значения его источник. Команда только читает файлы. С `--global-config PATH` она показывает этот общий файл, но не подключает его: личный файл не меняется. С `--project P` выводятся только настройки проекта `P` (`projects.<ключ>.…`) и его путь `image_cache`. Работает без терминала.

```text
$ cveta2 setup --list
Общая конфигурация: /home/user/team/project-config.yaml
cvat.host = https://cvat.example.com  (общая)
cvat.organization = my-team  (общая)
cvat.username = alice  (личная)
cvat.password = ***  (личная)
cache.images_root = /data/img  (личная)
image_cache.Retail shelves = /data/retail  (личная)
network.s3_workers = 3  (окружение)
network.cvat_workers = 4  (по умолчанию)
network.retry_attempts = 5  (по умолчанию)
network.retry_max_wait = 30.0  (по умолчанию)
upload.images_per_job = 100  (по умолчанию)
upload.image_quality = 100  (по умолчанию)
local_overrides = True  (общая)
projects.retail.id = 123  (общая)
projects.retail.name = Retail shelves  (общая)
projects.retail.sync_root = s3://my-bucket/images  (общая)
projects.retail.publication.clearml.project = Retail/Datasets  (общая)
projects.retail.publication.clearml.dataset = retail-shelves-alice  (локальное переопределение)
projects.retail.publication.api_url = https://classes.example.com/api  (общая)
projects.retail.publication.empty_classes = [12, 13]  (общая)
```

Первая строка есть, только если общий файл выбран. Источники:

| Метка | Откуда значение |
|---|---|
| `окружение` | Переменная окружения, которую читает cveta2: `CVAT_HOST`, `CVAT_ORGANIZATION`, `CVAT_USERNAME`, `CVAT_PASSWORD`, `CVETA2_DATA_TIMEOUT`, `CVETA2_S3_WORKERS`, `CVETA2_CVAT_WORKERS`, `CVETA2_RETRY_ATTEMPTS`. Некорректное значение переменной не применяется и не показывается. Когда общий файл подключён, адрес и организация CVAT берутся из него, а не из `CVAT_HOST` и `CVAT_ORGANIZATION`. |
| `локальное переопределение` | Раздел `overrides` личного файла. |
| `общая` | Общий файл: `cvat.*`, `local_overrides`, `projects.*`. |
| `личная` | Личный файл. |
| `по умолчанию` | Встроенное значение по умолчанию. |

Если источников несколько, показывается первый по этой таблице: переменная окружения важнее файлов. Незаданные значения не выводятся. Пароль всегда показывается как `***`, откуда бы он ни был взят.

Если личный файл содержит переопределения, а общий файл их не разрешает, `--list` не останавливается: он показывает значения общего файла и рядом переопределения с пометкой `(локальное переопределение; не применяется: общая конфигурация не разрешает переопределения)`. Остальные команды в этом состоянии завершаются ошибкой (см. [Частые ошибки](#частые-ошибки)).

Списки игнорируемых задач и описания наборов данных `--list` не выводит: для них есть [`cveta2 ignore --list`](ignore.md) и [`cveta2 dataset list`](dataset.md#list). `--list` заменяет прежний `cveta2 setup-cache --list`. [`cveta2 doctor`](doctor.md) проверяет конфигурацию, но источники значений не показывает.

### Запись значений

Команда ничего не спрашивает (кроме пароля для `--password`) и записывает каждый файл не больше одного раза:

- С `--global` все значения записываются в общий файл одной записью под блокировкой (см. [Запись в общий файл и блокировка](../configuration.md#запись-в-общий-файл-и-блокировка)). Основа записи — сам общий файл, ваши переопределения туда не попадают. После записи общий файл проверяется целиком: если блок `publication` стал неполным, запись отклоняется.
- Без `--global` настройки публикации записываются в раздел `overrides` личного файла, остальное — в разделы `cvat`, `cache` и `image_cache` личного файла.

Для каждого изменённого файла выводится строка, например `Записано в общую конфигурацию /home/user/team/project-config.yaml: projects.retail.publication.clearml.dataset` или `Удалено из личной конфигурации <путь>: overrides.projects.retail.publication.clearml.dataset`.

Локальное переопределение записывается, только если общий файл разрешает переопределения (`local_overrides: true`) и результат слияния корректен. Удалить своё переопределение (`--unset`) можно, даже если общий файл их не разрешает или проекта в нём больше нет. Перед удалением команда проверяет оставшиеся переопределения всех проектов и отклоняет удаление, если они станут некорректными:

- удаление одного значения оставило бы блок неполным (например, в общем файле у проекта нет `publication`) — удалите весь блок командой `cveta2 setup --project P --unset publication`;
- после удаления значения или всего блока назначение ClearML проекта совпало бы с назначением из переопределения другого проекта — сначала удалите или измените то переопределение.

Если переопределения были некорректны ещё до команды, удаление не отклоняется: так их и исправляют.

Команды `--global …` (в том числе `--global --local-overrides on`) и `--project P --unset …` без `--global` работают и тогда, когда личный файл содержит переопределения, которые общий файл не разрешает: ими это состояние и исправляют. Исключение — добавление проекта, имя которого приходится узнавать у CVAT: подключение к CVAT читает итоговую конфигурацию и в этом состоянии отклоняется.

### Как выбирается проект

`--project` ищется в общем файле сначала как ключ `projects.<ключ>`, затем как значение `name`, затем как ID. Для `--images-dir` ключом раздела `image_cache` служит имя проекта (`name`, а если оно пустое — ключ).

С `--global` проект, которого ещё нет в общем файле, получает описание. ID и имя берутся из списка проектов `projects.yaml` рядом с личным файлом, а если там проекта нет — из CVAT. Для этого нужны логин и пароль, поэтому сначала выполните личную настройку. Ключ нового описания — имя проекта, если оно состоит из латиницы, цифр, `_` и `-` и начинается с буквы или цифры; иначе `project-<ID>` (то же правило, что при переносе). Если ни список, ни CVAT не знают проект, команда отказывается: описание без имени не совпало бы ни с одним проектом. `--unset` новых описаний не создаёт.

Без `--global` проект для локального переопределения должен быть описан в общем файле. Иначе: `Нет описания проекта <P> в общей конфигурации; добавьте его: cveta2 setup --global --project <P>`.

### Создание общего файла

`cveta2 setup --global --global-config PATH --host URL [--organization SLUG]` создаёт общий файл, если по пути `PATH` файла нет. Путь можно задать и переменной `CVETA2_GLOBAL_CONFIG`.

1. Создаёт файл с `schema_version: 1`, `local_overrides: true` и разделом `cvat`. Существующий файл никогда не перезаписывается.
2. Подключает его к личному файлу, как [подключение](#подключение-общего-файла---global-config). Адрес и организация в личном файле старого формата должны совпасть с новыми; тогда они удаляются из личного файла. Если подключение не удалось, новый файл удаляется.
3. Остальные флаги той же команды записываются в новый файл.

Если путь задан, но файла нет, а `--host` не указан, команда останавливается и показывает эту форму.

### Подключение общего файла (`--global-config`)

1. Читает личный файл (если его нет, считает его пустым).
2. Читает и проверяет общий файл. Ошибка в общем файле останавливает команду.
3. Записывает в личный файл `schema_version: 1` и абсолютный путь в `global_config`. Старый ключ `project_config`, если он был, удаляется. Остальное содержимое личного файла сохраняется.
4. Общий файл не меняется. Выводит `Общая конфигурация подключена: <путь>`.
5. Если заданы флаги-значения или `--unset`, записывает их, как описано выше.

Если в личном файле есть `cvat.host` или `cvat.organization` либо ключи общего файла, команда не подключает файл и требует `--migrate-config`.

### Мастер настройки (без флагов)

1. Если общий файл уже подключён, проверяет, что `CVAT_HOST` и `CVAT_ORGANIZATION` не противоречат ему.
2. Задаёт вопросы по очереди (в квадратных скобках — текущее значение, Enter его оставляет):

   | Вопрос | Когда задаётся | Что ввести |
   |---|---|---|
   | `Хост CVAT [<значение>]:` | Общий файл не подключён. | Адрес CVAT, например `https://cvat.example.com`. По умолчанию — адрес из личного файла или `https://app.cvat.ai`. |
   | `Slug организации [<значение>]:` | Общий файл не подключён. | Slug, например `my-team`. |
   | `Организация не указана. Подтвердите, что у вас нет организации` | Slug оставлен пустым. | «Да» — работать в личном пространстве. «Нет» — вопрос о slug повторяется. |
   | `Имя пользователя [<значение>]:` | Всегда. | Логин CVAT. |
   | `Пароль:` | Всегда. | Пароль, ввод не отображается. Пустой ввод оставляет сохранённый пароль: `Пароль не изменён (использован существующий).` |

   Когда общий файл подключён, адрес и организация берутся из него, и первые три вопроса не задаются.
3. Записывает раздел `cvat` в личный файл с правами `0600`. Остальные разделы сохраняются. `cvat.request_timeout` сохраняется без изменений. Выводит `Готово! Конфигурация сохранена в <путь>`.
4. Если общий файл не был подключён, спрашивает `Общий YAML проектов (пусто — пропустить):`.
   - Пусто — команда завершается.
   - Путь к существующему файлу — подключает его. Адрес и организация, которые вы ввели, должны совпасть с общим файлом. Тогда они удаляются из личного файла, и в нём остаются `schema_version: 1` и `global_config`.
   - Путь к несуществующему файлу — строит предложение переноса (как `--migrate-config`), выводит его и спрашивает `Подтвердить разделение и подключение?` (по умолчанию «нет»). При «да» создаёт общий файл по этому пути с адресом, организацией и проектами, ID которых известны из `projects.yaml`, и подключает его.

Логин и пароль cveta2 не проверяет на сервере: команда только записывает их. Проверить подключение можно любой командой, которая обращается к CVAT, например [`cveta2 labels`](labels.md).

### Перенос старой конфигурации (`--migrate-config`)

1. Если есть журнал прерванного переноса `<личный файл>.migration.json`, завершает тот перенос и выходит: `Прерванное подтверждённое разделение конфигурации завершено.`
2. Строит предложение: какие ключи остаются в личном файле, какие уходят в общий. Проект переносится, только если его ID однозначно известен из `projects.yaml` рядом с личным файлом. Общий файл по умолчанию — `project-config.yaml` рядом с личным файлом.
3. Выводит предложение как JSON. Логин и пароль заменены на `<redacted>`:

   ```text
   {
     "personal_path": "/home/user/.config/cveta2/config.yaml",
     "shared_path": "/home/user/.config/cveta2/project-config.yaml",
     "personal": {
       "cvat": {"username": "<redacted>", "password": "<redacted>"},
       "cache": {"images_root": "/home/user/data", "projects": {}},
       "schema_version": 1,
       "global_config": "/home/user/.config/cveta2/project-config.yaml"
     },
     "shared": {
       "schema_version": 1,
       "cvat": {"host": "https://cvat.example.com", "organization": "my-team"},
       "projects": {
         "project-123": {"id": 123, "name": "Retail shelves", "sync_root": "s3://my-bucket/images",
                         "ignored_prefix": null, "task_cache_s3": null, "ignore": []}
       },
       "datasets": {}
     },
     "unresolved": []
   }
   ```

   Ключ проекта в общем файле — имя проекта, если оно состоит из латиницы, цифр, `_` и `-` и начинается с буквы или цифры; иначе `project-<ID>`.
4. Если список `unresolved` не пуст, команда завершается ошибкой и ничего не записывает.
5. Спрашивает `Подтвердить показанное разделение конфигурации?` (по умолчанию «нет»). При «нет»: `Разделение отменено; конфигурация не изменена.`
6. При «да» сохраняет копию старого личного файла `<имя>.pre-v1-<первые 12 символов хеша>.bak`, записывает журнал, создаёт общий файл и заменяет личный файл. Выводит `Разделение конфигурации завершено.`

Если старый личный файл изменился между показом и подтверждением, перенос отклоняется. Существующий общий файл с другим содержимым не перезаписывается. Общий файл, созданный переносом, не содержит `local_overrides`: переопределения в нём не разрешены, пока команда не выполнит `cveta2 setup --global --local-overrides on`.

## Результат

| Файл | Когда меняется |
|---|---|
| Личный файл (`--config`) | Мастер, подключение, создание общего файла, перенос, личные флаги-значения и локальные переопределения. Права `0600`, запись атомарная. |
| Общий файл | С `--global` (запись под блокировкой, права и группа файла сохраняются); при создании и при переносе — создаётся. |
| `<личный файл>.pre-v1-<хеш>.bak` | При переносе: копия старого личного файла. |
| `<личный файл>.migration.json` | Во время переноса; удаляется после завершения. |

### Коды завершения

| Код | Когда |
|---|---|
| `0` | Настройки сохранены, или перенос отменён ответом «нет». |
| `1` | Недопустимое сочетание флагов, ошибка конфигурации, нет терминала при нужном вопросе, неразрешённые пункты переноса. |
| `2` | Ошибка разбора аргументов, например неизвестное имя в `--unset` или значение после `--password`. |

## Интерактивный и неинтерактивный режим

`--list`, флаги-значения, `--unset`, подключение и создание общего файла работают без терминала. Исключение — `--password`: с `CVETA2_NO_INTERACTIVE=true` он сразу завершается с кодом 1 и подсказкой `Задайте пароль через CVAT_PASSWORD или запустите cveta2 setup --password в терминале.`, а без терминала — с кодом 1 и сообщением `Interactive prompt required but standard input is closed. ...`. Файлы в обоих случаях не меняются.

Мастер настройки и `--migrate-config` работают только в терминале. С `CVETA2_NO_INTERACTIVE=true` они сразу завершаются с кодом 1. Без терминала (но без `CVETA2_NO_INTERACTIVE=true`) мастер завершается с кодом 1 на первом вопросе, а `--migrate-config` сначала выводит предложение переноса и завершается с кодом 1 на вопросе о подтверждении; файлы не меняются.

## Частые ошибки

Недопустимые сочетания флагов. Команда проверяет их до первой записи и ничего не меняет. Правила действуют и для имён в `--unset`: `--global --unset username` отклоняется так же, как `--global --username`.

| Сочетание | Сообщение (начало) | Что сделать |
|---|---|---|
| `--list` с флагом-значением, `--unset`, `--reset`, `--global` или `--migrate-config` | `--list только показывает настройки и не сочетается с --username; уберите --username.` | Сначала посмотрите настройки, затем запишите значения отдельной командой. |
| `--migrate-config` с флагом-значением, `--unset`, `--global`, `--project` или `--reset` | `--migrate-config выполняется отдельно: ...` | Запустите перенос отдельной командой. |
| Флаги-значения вместе с `--unset` | `--unset нельзя сочетать с новыми значениями; ...` | Разделите на две команды. |
| `--reset` с флагами-значениями, `--unset` или `--global` | `--reset относится только к мастеру настройки кэша; ...` | Уберите `--reset`. |
| `--global` с `--username`, `--password`, `--images-root`, `--tasks-root` или `--images-dir` | `--username относится к личной конфигурации; уберите --global.` | Уберите `--global`. |
| `--local-overrides` без `--global` | `--local-overrides задаётся только в общей конфигурации: cveta2 setup --global --local-overrides on\|off` | Добавьте `--global`. |
| `--sync-root`, `--ignored-prefix` или `--task-cache-s3` без `--global` | `--sync-root задаётся только в общей конфигурации, локально не переопределяется: cveta2 setup --global --project P --sync-root …` | Добавьте `--global`: эти настройки одинаковы для всей команды. |
| Настройка публикации без `--global`, когда общий файл не выбран | `Настройки публикации хранятся только в общей конфигурации, а она не выбрана; без неё передайте значения команде verify.` | Подключите общий файл или передайте значения флагами `verify`. |
| `--images-dir` или настройка проекта без `--project` | `--dataset-name относится к проекту; укажите его: --project P` | Добавьте `--project`. |
| `--host` или `--organization` без `--global`, когда общий файл подключён | `--host: хост и организация CVAT задаются в общей конфигурации: cveta2 setup --global --host URL [--organization SLUG]` | Добавьте `--global`: адрес меняется в общем файле. |
| `--global` со значениями или `--unset`, а общий файл не выбран | `Общая конфигурация не выбрана; создайте её: cveta2 setup --global --global-config PATH --host URL [--organization SLUG]` | Подключите общий файл или создайте его этой формой. |
| `--global` без `--host`, а файла по пути `--global-config` (или `CVETA2_GLOBAL_CONFIG`) нет | `Файла общей конфигурации <путь> нет; создайте его: cveta2 setup --global --global-config PATH --host URL [--organization SLUG]` | Проверьте путь или создайте файл с `--host`. |

Другие ошибки:

| Сообщение | Причина | Что сделать |
|---|---|---|
| `Личная конфигурация содержит локальные переопределения (...), но общая конфигурация их не разрешает. ...` | Локальное переопределение при выключенном `local_overrides`. | Попросите того, кто ведёт общий файл, выполнить `cveta2 setup --global --local-overrides on`, или удалите переопределение: `cveta2 setup --project P --unset publication`. |
| `Нет описания проекта <P> в общей конфигурации; добавьте его: cveta2 setup --global --project <P>` | Локальное переопределение проекта, которого нет в общем файле. | Сначала добавьте описание проекта в общий файл. |
| `Без publication.api_url локальные переопределения станут некорректными: ... Удалите весь блок: cveta2 setup --project P --unset publication; ...` | После удаления одного значения блок переопределения стал бы неполным, или назначение ClearML совпало бы с назначением другого переопределения (оно названо в сообщении). | Удалите весь блок или сначала измените совпадающее переопределение другого проекта. Если переопределения уже некорректны до команды, удаление не отклоняется. |
| `Без publication локальные переопределения станут некорректными: ... Сначала удалите или измените совпадающее переопределение другого проекта.` | После удаления всего блока назначение ClearML проекта совпало бы с назначением из переопределения другого проекта (оно названо в сообщении). | Сначала удалите или измените то переопределение, затем повторите. |
| `Общая конфигурация <путь> после изменения некорректна; поля: projects.<ключ>.publication...` | Запись в общий файл оставила бы блок `publication` неполным или с неверным значением. | Задайте недостающие значения той же командой или удалите блок: `--unset publication`. |
| `Не удалось определить имя проекта <P>; проверьте ID или учётные данные CVAT.` | Нового проекта нет ни в `projects.yaml`, ни в CVAT. | Проверьте ID или имя и личные настройки CVAT. |
| `Нет описания проекта <P> в общей конфигурации; удалять нечего.` | `--global --unset` для проекта без описания. | Проверьте `--project`. |
| `Файл <путь> уже существует; подключите его: cveta2 setup --global-config <путь>` | Общий файл создаётся поверх существующего. | Подключите существующий файл. |
| `Задайте пароль через CVAT_PASSWORD или запустите cveta2 setup --password в терминале.` | `--password` без терминала. | Задайте `CVAT_PASSWORD` или запустите в терминале. |
| `Interactive prompt required but CVETA2_NO_INTERACTIVE=true. The 'setup' command is fully interactive. ...` | Мастер или перенос запущены в неинтерактивном режиме. | Запустите в терминале без `CVETA2_NO_INTERACTIVE=true` или используйте флаги-значения и переменные окружения. |
| `Interactive prompt required but standard input is closed. ...` | Нет терминала (cron, CI). | То же. |
| `Cannot read configuration <путь>: FileNotFoundError` | Файла по пути `--global-config` нет. | Проверьте путь к общему файлу. |
| `Invalid shared project configuration: <путь>` | Общий файл не прошёл проверку. | Сообщите тому, кто ведёт общий файл. |
| `Legacy mixed configuration requires verification: cveta2 setup --migrate-config` | В личном файле есть адрес CVAT или ключи общего файла. | Запустите `cveta2 setup --migrate-config`. |
| `CVAT host/organization in <личный файл> differ from shared configuration <общий файл>; correct them in setup or choose the shared file of that server` | Введён другой адрес или организация, чем в общем файле. | Запустите команду ещё раз с данными из общего файла или выберите общий файл своего сервера. |
| `CVAT identity environment overrides conflict with shared project configuration` | `CVAT_HOST` или `CVAT_ORGANIZATION` не совпадают с общим файлом. | Уберите эти переменные. |
| `Сначала устраните неоднозначные настройки из отчёта миграции.` | В предложении переноса есть пункты `unresolved`. | Исправьте старый файл по списку и повторите. |
| `Общая конфигурация отличается; выполните setup --migrate-config после согласования.` | В конце мастера перенос дал пункты `unresolved`. | То же. |
| `Configuration changed after migration preview; review again` | Личный файл изменился во время переноса. | Повторите команду. |
| `Migration journal <путь> is unreadable or damaged ...` | Журнал прерванного переноса повреждён. | Сделайте то, что написано в сообщении: проверьте файлы, удалите журнал и повторите. |

## Из Python

Отдельной функции для `setup` нет: Python API ничего не спрашивает. Настройки, которые увидит API, можно проверить через `cveta2.CvatConfig`:

```python
import cveta2

cfg = cveta2.CvatConfig.load()  # значения по умолчанию < личный файл < окружение
cfg.require_credentials()  # MissingCredentialsError, если нет логина или пароля
print(cfg.host, cfg.organization)
```

`CvatConfig.load(config_path=None, *, project_path=None)` возвращает `CvatConfig`. Ошибки в файлах приводят к `cveta2.Cveta2Error`. Как передать подключение в функции API — на странице [Python API](../python-api.md).
