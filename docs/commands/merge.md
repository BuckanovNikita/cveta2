# cveta2 merge

Объединяет два CSV с аннотациями в один: для изображения, которое есть в обоих файлах, берёт аннотации только из одного. Нужна, когда к старому датасету надо добавить свежую выгрузку и при этом не потерять уже назначенный split.

## Примеры

Объединить старый датасет с новой выгрузкой; для общих изображений побеждает новая выгрузка:

```bash
cveta2 merge --old ~/data/old/dataset.csv --new output/dataset.csv -o ~/data/merged.csv
```

То же, но убрать удалённые изображения и изображения, которые снова в работе:

```bash
cveta2 merge --old ~/data/old/dataset.csv --new output/dataset.csv \
  --deleted output/deleted.csv --in-progress output/in_progress.csv -o ~/data/merged.csv
```

Решать конфликты по номеру задачи (task), а не по порядку аргументов:

```bash
cveta2 merge --old ~/data/a.csv --new ~/data/b.csv --by-task -o ~/data/merged.csv
```

## Синтаксис и аргументы

```text
cveta2 merge [-h] --old OLD --new NEW [--deleted DELETED]
             [--in-progress IN_PROGRESS] --output OUTPUT [--by-task]
```

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--old` | обязательный | Старый (базовый) CSV. |
| `--new` | обязательный | Новый CSV. |
| `--deleted` | нет | `deleted.csv`. Изображения из него удаляются из результата, из обоих файлов. Подходит и старый формат: простой текст, одно имя файла в строке. |
| `--in-progress` | нет | `in_progress.csv` новой выгрузки. Из старого файла удаляются изображения с переоткрытым удалением ([reopened deletion](../../GLOSSARY.md)). |
| `--output`, `-o` | обязательный | Куда записать результат. Каталоги создаются. Существующий файл перезаписывается. |
| `--by-task` | выкл. | Решать конфликт по наибольшему `task_id` изображения в каждом файле. Нужен столбец `task_id` в обоих файлах. |
| `-h`, `--help` | | Показать справку. |

## Как это работает

1. Команда читает `--old` и `--new`. В обоих файлах должны быть столбцы `image_name`, `instance_label`, `instance_shape`, `bbox_x_tl`, `bbox_y_tl`, `bbox_x_br`, `bbox_y_br` (см. [Формат датасета](../dataset-format.md)). С `--by-task` нужен ещё `task_id`.
2. С `--deleted` команда читает имена изображений из столбца `image_name` файла.
3. С `--in-progress` команда находит в нём изображения со строками, где `task_completed` равно `True`. Так в файл «в работе» ([in progress](../../GLOSSARY.md)) попадает изображение, чьё последнее завершённое удаление снова взяла в работу более новая незавершённая задача. Строки незавершённых задач на результат не влияют.
4. Команда сравнивает изображения по `image_name`, а не по отдельным строкам. Изображение берётся целиком, со всеми его строками, из одного файла.
   - Изображение есть только в `--old`: строки берутся из `--old`.
   - Изображение есть только в `--new`: строки берутся из `--new`.
   - Изображение есть в обоих (конфликт): без `--by-task` побеждает `--new`. С `--by-task` для каждого файла берётся наибольший `task_id` строк этого изображения; побеждает `--new`, если его `task_id` больше или равен, иначе `--old`. Если в одном из файлов `task_id` пустой или не число, побеждает `--new`.
5. Изображения из `--deleted` удаляются из обоих файлов. Изображения из `--in-progress` (шаг 3) удаляются только из `--old`. Если такое изображение есть в `--new` и `--new` победил в конфликте, его строки из `--new` остаются. Если с `--by-task` победил `--old`, изображения в результате не будет совсем.
6. Строки собираются в таком порядке: сначала оставленные строки `--old`, затем оставленные строки `--new`.
7. Заполняется split (см. ниже), результат записывается в `--output`.

### Что происходит со split

Значение split изображения сохраняется из старого файла:

- если у строки результата `split` пустой, а в `--old` у этого изображения split задан, значение копируется из `--old`; берётся split первой строки изображения в `--old`, у которой он задан;
- заполненный `split` в результате не меняется: если изображение победило из `--new` со своим split, остаётся split из `--new`;
- если split задан в обоих файлах для общего изображения, команда предупреждает: `split задан в обоих датасетах для 3 изображений — используется значение из победившей стороны`;
- если в `--old` нет столбца `split` или он пустой во всех строках, команда предупреждает `В old-датасете нет данных split — пропагация split невозможна` и ничего не заполняет;
- новые изображения, которых нет в `--old`, остаются с пустым split. Назначить им split должны вы.

Пример. В `--old` изображение `shelf_001.jpg` с `split` = `val` из задачи 455. В `--new` то же изображение из задачи 456 без split. Без `--by-task` в результате будут строки из задачи 456 с `split` = `val`.

## Результат

Один CSV в `--output` со столбцами обоих файлов. Команда печатает сводку:

```text
Результат слияния: только в old=1, только в new=1, конфликт→new=6, конфликт→old=0, удалено=0, снова в работе=0, итого строк=30
```

| Поле | Что значит |
|---|---|
| `только в old`, `только в new` | Изображения только в одном файле, без удалённых. |
| `конфликт→new`, `конфликт→old` | Общие изображения и сторона, которая победила. |
| `удалено` | Изображения из `--deleted`, найденные в файлах. |
| `снова в работе` | Изображения из `--in-progress`, которые убраны из `--old`. |
| `итого строк` | Строк в результате. |

Затем печатается путь записанного файла с числом изображений и строк. Если split скопирован, перед сводкой печатается `Пропагация split: заполнено 16 строк из old-датасета`.

### Коды завершения

| Код | Когда |
|---|---|
| 0 | Результат записан. |
| 1 | Файл не найден, пустой или нечитаемый; нет обязательного столбца. |
| 2 | Неверные аргументы командной строки, например нет `--old`. |

## Интерактивный и неинтерактивный режим

Команда ничего не спрашивает и одинаково работает с `CVETA2_NO_INTERACTIVE=true` и без него. Она не подключается к CVAT.

## Частые ошибки

**`Ошибка: файл не найден: output/dataset.csv`**

Неверный путь в `--old`, `--new`, `--deleted` или `--in-progress`.

**`Ошибка: в old.csv отсутствуют обязательные столбцы: bbox_x_br, bbox_x_tl, bbox_y_br, bbox_y_tl, instance_label, instance_shape`**

Файл не похож на выгрузку cveta2. Проверьте, что это `dataset.csv` или его копия.

**`Ошибка: --by-task требует столбец 'task_id' в old.csv, но он отсутствует.`**

Для `--by-task` в обоих файлах нужен `task_id`. Уберите `--by-task` или добавьте столбец.

## Из Python

```python
cveta2.merge(old, new, output, *, deleted=None, in_progress=None, by_task=False) -> pandas.DataFrame
```

Параметры совпадают с флагами. Функция записывает файл `output` и возвращает объединённую таблицу. При ошибке во входных файлах поднимается `cveta2.Cveta2Error`. Подключение к CVAT не нужно.

```python
import cveta2

merged = cveta2.merge(
    "data/old/dataset.csv",
    "output/dataset.csv",
    "data/merged.csv",
    deleted="output/deleted.csv",
    in_progress="output/in_progress.csv",
)
print(len(merged))
```
