# cveta2 upload

Создаёт в проекте CVAT новую задачу (task) из CSV: загружает недостающие изображения в S3, привязывает их к задаче, переносит bbox-аннотации и замечания (issue) и помечает удалённые кадры (frame). Нужна, когда размеченные или исправленные данные надо вернуть в CVAT, например для повторной проверки.

> **Внимание.** Каждый успешный запуск создаёт новую задачу. Повторный запуск той же команды после успешного завершения создаёт вторую задачу с теми же кадрами. Лишнюю задачу удаляет только [`cveta2 task delete`](task.md#delete), и это удаление нельзя отменить.

## Примеры

Загрузить все кадры, на которых есть метка (label) `bottle`, и назвать задачу:

```bash
cveta2 upload -p "Retail shelves" -d output/dataset.csv --labels bottle --name "bottle-review"
```

Загрузить все кадры CSV, включая кадры без аннотаций, но без изображений, которые сейчас в работе, и искать изображения ещё и в `~/data/images`:

```bash
cveta2 upload -p 123 -d output/dataset.csv --labels all --name "recheck" \
  --in-progress output/in_progress.csv --image-dir ~/data/images
```

Продолжить загрузку из второго примера, если она оборвалась: та же команда целиком, плюс `--resume`:

```bash
cveta2 upload -p 123 -d output/dataset.csv --labels all --name "recheck" \
  --in-progress output/in_progress.csv --image-dir ~/data/images --resume
```

## Синтаксис и аргументы

```text
cveta2 upload [-h] [--project PROJECT] --dataset DATASET
              [--labels LABEL [LABEL ...]] [--in-progress IN_PROGRESS]
              [--image-dir IMAGE_DIR] [--name NAME] [--complete]
              [--mark-all-deleted] [--resume]
```

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--project`, `-p` | выбор в терминале | ID или имя проекта. Можно указать организацию: `my-team/Retail shelves`; `/Retail shelves` выбирает личное пространство. Без префикса организация берётся из конфигурации. |
| `--dataset`, `-d` | обязательный | CSV с аннотациями. Обычно это `dataset.csv` из [`cveta2 fetch`](fetch.md) или его изменённая копия. |
| `--labels` | выбор в терминале | Одна или несколько меток. Они выбирают кадры: в задачу попадает каждый кадр, на котором есть хотя бы одна из этих меток, со всеми его аннотациями. `__no_annotation__` выбирает кадры без аннотаций. `--labels all` выбирает все метки CSV и кадры без аннотаций. |
| `--in-progress` | нет | Путь к `in_progress.csv`. Изображения из его столбца `image_name` исключаются из загрузки. |
| `--image-dir` | нет | Ещё один каталог для поиска изображений на диске. Его просматривают раньше кэша изображений проекта. Можно указать только один каталог. |
| `--name` | ввод в терминале | Имя новой задачи. |
| `--complete` | выкл. | После загрузки перевести все job задачи в stage `acceptance`, state `completed`. |
| `--mark-all-deleted` | выкл. | Пометить удалёнными все кадры новой задачи. |
| `--resume` | выкл. | Продолжить незавершённую загрузку тех же данных вместо создания новой задачи. |
| `-h`, `--help` | | Показать справку. |

## Как это работает

### Какие столбцы нужны

Обязательны только `image_name` и `instance_label` (формат столбцов описан в [Формат датасета](../dataset-format.md)). Остальные столбцы используются, если они есть:

| Столбцы | Для чего |
|---|---|
| `bbox_x_tl`, `bbox_y_tl`, `bbox_x_br`, `bbox_y_br` | Координаты bbox в пикселях. Строка с меткой должна иметь все четыре конечных числа, иначе загрузка не начинается. |
| `instance_shape` | Строки со значением `deleted` описывают удалённые кадры. |
| `issue_state`, `issue_text` | Строка с `issue_state` = `new` и непустым `issue_text` становится замечанием в CVAT. |

Строки без метки описывают кадр без аннотаций.

### Шаги

1. Команда читает CSV. Строки с `instance_shape` = `deleted` откладываются: их изображения станут удалёнными кадрами.
2. Если указан `--in-progress`, команда читает из него `image_name` и исключает эти изображения, в том числе из удалённых кадров.
3. Команда подключается к CVAT, находит проект, спрашивает имя задачи и метки, если их нет в аргументах.
4. Метки выбирают кадры. В задачу попадают все строки выбранных кадров, в том числе строки с невыбранными метками. Удалённые кадры попадают в задачу всегда, независимо от `--labels`. Если не осталось ни одного кадра, команда завершается с ошибкой.
5. Порядок кадров в задаче совпадает с порядком первого появления изображения в CSV. Удалённые кадры идут после обычных.
6. Команда проверяет имена изображений и bbox, затем вычисляет отпечаток загрузки ([upload fingerprint](../../GLOSSARY.md)): кадры, удалённые кадры, метки, строки аннотаций, имя задачи, настройки `upload` и флаги `--complete`, `--mark-all-deleted`. На время работы ставится блокировка, чтобы два одинаковых запуска не шли одновременно.
7. Команда проверяет, что все метки выбранных строк есть в проекте CVAT.
8. Команда ищет изображения на диске (см. ниже) и определяет облачное хранилище (cloud storage) проекта (S3, к которому привязан проект в CVAT).
9. Команда читает список объектов в S3 и решает, где лежит каждое изображение (см. ниже). Если изображения нет ни на диске, ни в S3, команда завершается, задача не создаётся.
10. Изображения, найденные на диске, которых ещё нет в S3, загружаются в S3. Уже загруженные пропускаются. Если хотя бы одно изображение не загрузилось, команда завершается, задача не создаётся. При повторном запуске загруженные изображения будут пропущены.
11. Команда сохраняет манифест загрузки ([upload manifest](../../GLOSSARY.md)) и только потом создаёт задачу в CVAT. ID новой задачи записывается в манифест сразу после создания, до привязки изображений.
12. Изображения привязываются к задаче из облачного хранилища. Порядок кадров задаётся явно. Число кадров в одном job задаёт настройка `upload.images_per_job` (по умолчанию 100), качество изображений в CVAT задаёт `upload.image_quality` (по умолчанию 100). Обе настройки описаны в [Конфигурации](../configuration.md). Команда ждёт, пока CVAT обработает изображения.
13. В задачу записываются bbox-аннотации: строки с меткой и полными координатами. Признаки `occluded`, `z_order`, `rotation`, атрибуты и `confidence` из CSV не переносятся.
14. Создаются замечания (issue): по одному на каждую строку с `issue_state` = `new` и непустым `issue_text`. Замечание ставится на кадр в job, который содержит этот кадр, в прямоугольник bbox строки. Строка без полного bbox замечания не создаёт. Полностью одинаковые строки (изображение, текст, bbox) дают одно замечание.
15. Удалённые кадры помечаются удалёнными. С `--mark-all-deleted` удалёнными помечаются все кадры задачи.
16. С `--complete` все job задачи переводятся в stage `acceptance`, state `completed`.
17. Команда сбрасывает запись новой задачи в кэше аннотаций ([annotation cache](../../GLOSSARY.md)), записывает итог в манифест и удаляет манифест.

### Где команда ищет изображения

Команда ищет файлы по `image_name` в таком порядке:

1. каталог из `--image-dir`;
2. кэш изображений ([image cache](../../GLOSSARY.md)) проекта: каталог из раздела `image_cache` для этого проекта, а если его нет, каталог из `cache.images_root` (см. [Изображения и кэши](../images-and-cache.md)).

В каждом каталоге сначала проверяется путь `<каталог>/<image_name>`, затем поиск идёт по имени файла во всех подкаталогах. Если файл с таким именем лежит в нескольких подкаталогах, берётся путь, который последний по алфавиту. Каталог из списка, где файл найден раньше, побеждает. Имена с абсолютным путём или с `..` не ищутся и считаются ненайденными.

Если ни `--image-dir`, ни кэш изображений не заданы, команда предупреждает, что будут использованы только изображения, которые уже есть в S3.

### Куда изображения попадают в S3

Изображения кладутся в облачное хранилище проекта, под его префикс:

- если в S3 под префиксом уже есть файл с таким же именем (в любом подкаталоге), используется он, и изображение не загружается заново; при нескольких совпадениях берётся путь, последний по алфавиту;
- новое изображение кладётся в подкаталог текущего месяца по UTC: `<префикс>/YYYY-MM/<image_name>`.

Например, для облачного хранилища `s3://my-bucket/images` новый файл `shelf_001.jpg` в ноябре 2026 года попадёт в `s3://my-bucket/images/2026-11/shelf_001.jpg`.

### Прерванная загрузка и продолжение

Манифест загрузки хранится в кэше cveta2: `<кэш>/cveta2/uploads/<хеш сервера>/project_<ID проекта>/<отпечаток>.json`, рядом лежит файл блокировки `.lock`. Где находится каталог кэша, описано в [Изображения и кэши](../images-and-cache.md). Манифест удаляется после успешной загрузки.

Если запуск оборвался после создания задачи (сбой сети, остановка процесса), в CVAT остаётся задача, а на диске манифест. Повторный запуск той же команды без `--resume` новую задачу не создаёт и завершается сообщением:

```text
Найдена незавершённая загрузка этого набора (задача 456); повторное создание запрещено. Чтобы продолжить её, повторите команду с --resume. Состояние загрузки: <путь к манифесту>
```

Возобновление загрузки ([upload resume](../../GLOSSARY.md)) запускается той же командой с `--resume`. Данные должны совпадать с первым запуском: тот же CSV, те же `--labels`, `--in-progress`, `--name`, флаги и настройки `upload`, иначе отпечаток другой и манифест не найдётся. Проект и адрес сервера CVAT в конфигурации тоже должны совпадать: каталог манифеста зависит от адреса, и после смены адреса (например, другого порта) `--resume` манифест не находит. При продолжении команда:

1. проверяет, что облачное хранилище проекта не изменилось, и берёт размещение изображений в S3 из манифеста (даже если начался новый месяц);
2. если задача ещё существует, сверяет её проект, число и имена кадров и уже записанные аннотации с манифестом;
3. загружает в S3 недостающие изображения;
4. если задачи больше нет в CVAT (например, её удалили вручную), создаёт новую;
5. если в задаче уже есть все кадры, использует её; если аннотации уже полностью записаны, не пишет их повторно;
6. создаёт только те замечания, которых ещё нет в задаче, затем помечает удалённые кадры и с `--complete` завершает задачу.

Если загрузка уже завершилась, но манифест не удалился, повторный запуск (с `--resume` или без) печатает `Загрузка уже завершена: задача 456; запись не повторяется.`, ничего не пишет в CVAT и удаляет манифест.

### Чего нельзя делать вручную

- Не удаляйте и не правьте файл манифеста, пока задача из него существует. Без манифеста следующий запуск создаст вторую задачу. Удалять манифест можно, только когда команда сама это предлагает и вы убедились в CVAT, что задача не создана.
- Не меняйте кадры и аннотации задачи в CVAT между прерванным запуском и `--resume`. Продолжение сверяет задачу с манифестом и откажется писать, если кадры или аннотации отличаются.
- Не меняйте CSV, метки и флаги между прерванным запуском и `--resume`.
- Не запускайте команду повторно «на всякий случай» после успешного завершения: это создаст вторую задачу.

## Результат

Команда пишет в CVAT новую задачу, а в S3 — недостающие изображения. Локально она пишет и удаляет только манифест загрузки и сбрасывает запись задачи в кэше аннотаций. В конце печатается итог:

```text
Задача создана: id=456, имя='recheck', изображений=3, удалённых=1, аннотаций=4, issues=1, jobs≈1 (segment_size=100)
URL: https://cvat.example.com/tasks/456
```

`изображений` — все кадры задачи, включая удалённые; `удалённых` — кадры, помеченные удалёнными по строкам `deleted`. Кадры, помеченные через `--mark-all-deleted`, в это число не входят: о них сообщает отдельная строка `Помечено удалёнными N кадров в задаче <id>`.

### Коды завершения

| Код | Когда |
|---|---|
| 0 | Задача создана и заполнена, или загрузка уже была завершена раньше. |
| 1 | Любая ошибка: CSV, метки, изображения, S3, CVAT, манифест, нужен ввод в терминале без терминала. |
| 2 | Неверные аргументы командной строки, например нет `--dataset`. |

## Интерактивный и неинтерактивный режим

Если аргумента нет, в терминале команда спрашивает по порядку:

1. проект (выбор из списка), если нет `--project`;
2. имя задачи (`Имя задачи: `), если нет `--name`; пустое имя отменяет команду;
3. метки (`Выберите классы для загрузки:`, несколько из списка), если нет `--labels`. В списке есть пункт `(без аннотаций)`, если в CSV есть кадры без аннотаций. Если в CSV только удалённые кадры, выбор пропускается.

После ответов команда печатает полную команду с выбранными значениями, чтобы её можно было повторить без вопросов.

С `CVETA2_NO_INTERACTIVE=true` обязательны `--project`, `--name` и `--labels`. Без любого из них команда завершается с кодом 1 и сообщением вида:

```text
Interactive prompt required but CVETA2_NO_INTERACTIVE=true. Pass --name to specify the task name.
```

## Частые ошибки

```text
Ошибка: метки не найдены в dataset.csv: person.
Доступные: bottle, bowl, can
```

В `--labels` указана метка, которой нет в CSV. Выберите метку из списка `Доступные`.

**`Метки из CSV не найдены в проекте 'Retail shelves': tin. Доступные метки: bottle, can.`**

У выбранных кадров есть метки, которых нет в проекте CVAT. Добавьте метку в проект ([`cveta2 labels`](labels.md)) или исправьте CSV.

**`Ошибка: после фильтрации не осталось изображений.`**

Ни один кадр не подошёл под `--labels` или все кадры исключены через `--in-progress`.

**`Ошибка: 1 изображений нет ни локально, ни на S3: shelf_001.jpg. Задача не создана.`**

Изображение не найдено ни в `--image-dir`, ни в кэше изображений, ни в S3. Укажите правильный `--image-dir` или скачайте изображения ([`cveta2 s3-sync`](s3-sync.md)).

**`Неполный или некорректный bbox: строка 12, изображение 'shelf_001.jpg'. Загрузка не начата.`**

У строки с меткой нет одной из координат или она не число. `строка` — номер строки данных CSV с нуля, без заголовка: строка 12 — это 14-я строка файла.

**`Ошибка: cloud storage не найден для проекта 'Retail shelves' (id=123).`**

У проекта в CVAT нет облачного хранилища (source storage). Обратитесь к администратору CVAT.

**`Ошибка: 2 изображений не загрузились на S3 (s3://my-bucket/images). Задача не создана; ...`**

Сбой при загрузке в S3. Повторите команду: уже загруженные изображения будут пропущены.

**`Найдена незавершённая загрузка этого набора (задача 456); повторное создание запрещено. ...`**

Прошлый запуск оборвался. Повторите ту же команду с `--resume`.

**`Ошибка: незавершённых загрузок для проекта 'Retail shelves' не найдено — нечего продолжать.`**

`--resume` указан, а незавершённой загрузки нет. Если для проекта есть другие незавершённые загрузки, команда перечисляет их: значит, CSV, метки или флаги отличаются от того запуска.

**`Результат создания задачи неизвестен; проверьте CVAT вручную. Новая задача не создаётся. Если задача не создана, удалите состояние загрузки <путь> и повторите команду.`**

Запуск оборвался во время запроса на создание задачи, и ID задачи неизвестен. Найдите задачу в CVAT. Если её нет, удалите указанный файл манифеста и запустите команду снова. Если она есть, удалите её через `cveta2 task delete`, затем удалите манифест.

**`Задача 456 пока без изображений; результат привязки неизвестен. ...`**

CVAT ещё обрабатывает изображения задачи. Подождите и повторите `--resume`.

**`Задача 456: кадры не совпадают или привязка ещё не завершена; запись запрещена.`** и **`Задача 456: аннотации не совпадают с намерением загрузки ...`**

Задачу изменили после прерванного запуска, или CVAT ещё не закончил привязку изображений. Команда ничего не пишет. Проверьте задачу в CVAT.

**`Cloud storage проекта изменён; продолжение запрещено до записи.`**

Между запусками у проекта сменили облачное хранилище. Продолжить эту загрузку нельзя.

## Из Python

```python
cveta2.upload(dataset, project, name, *, labels=None, include_unannotated=False,
              exclude_in_progress=None, image_dirs=None, complete=False,
              mark_all_deleted=False, resume=False, connection=None) -> UploadResult
```

- `dataset` — путь к CSV или `pandas.DataFrame`.
- `project` — ID или имя проекта; `name` — имя задачи.
- `labels` — метки, которые выбирают кадры. `labels=None` выбирает все метки и кадры без аннотаций. Кадры без аннотаций при явном списке меток добавляет `include_unannotated=True`.
- `exclude_in_progress` — путь к `in_progress.csv` (как `--in-progress`).
- `image_dirs` — список каталогов для поиска изображений; в отличие от CLI, их может быть несколько. Символ `~` в пути не раскрывается, указывайте полный или относительный путь.
- `complete`, `mark_all_deleted`, `resume` — как одноимённые флаги.

Функция ничего не спрашивает. Она возвращает `UploadResult` с полями `task_id`, `task_name`, `url`, `images`, `deleted`, `annotations`, `issues`. При ошибке поднимается `cveta2.Cveta2Error` или его подкласс (`cveta2.CvatApiError` для ошибок CVAT).

```python
import cveta2

result = cveta2.upload(
    "output/dataset.csv",
    "Retail shelves",
    "bottle-review",
    labels=["bottle"],
    image_dirs=["data/images"],
)
print(result.task_id, result.url)
```

Параметр `connection` описан на странице [Python API](../python-api.md).
