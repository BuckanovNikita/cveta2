# cveta2 convert

Переводит CSV cveta2 в формат YOLO или COCO для обучения детектора и переводит разметку YOLO обратно в CSV cveta2. Нужна, когда датасет с назначенным split надо отдать в обучение, или когда предсказания модели надо превратить в CSV, например для [`cveta2 upload`](upload.md).

## Примеры

Выгрузить датасет в YOLO; изображения искать в `~/data/images`:

```bash
cveta2 convert --to-yolo -d ~/data/merged.csv -o output/yolo --image-dir ~/data/images
```

Выгрузить тот же датасет в COCO:

```bash
cveta2 convert --to-coco -d ~/data/merged.csv -o output/coco --image-dir ~/data/images
```

Превратить предсказания YOLO (`.txt` без `dataset.yaml`) в CSV с именами классов:

```bash
cveta2 convert --from-yolo -i output/predictions -o output/predictions.csv \
  --names-file ~/data/names.yaml --image-dir ~/data/images
```

## Синтаксис и аргументы

```text
cveta2 convert [-h] (--to-yolo | --from-yolo | --to-coco)
               [--dataset DATASET] [--input INPUT] --output OUTPUT
               [--link-mode {reflink,hardlink,symlink,copy,auto}]
               [--image-dir DIR [DIR ...]] [--names-file NAMES_FILE]
               [--read-all-sizes]
```

Нужно указать ровно одно направление: `--to-yolo`, `--from-yolo` или `--to-coco`.

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--to-yolo` | | CSV cveta2 → YOLO. Нужен `--dataset`. |
| `--from-yolo` | | YOLO → CSV cveta2. Нужен `--input`. |
| `--to-coco` | | CSV cveta2 → COCO. Нужен `--dataset`. |
| `--dataset`, `-d` | нет | Входной CSV для `--to-yolo` и `--to-coco`. |
| `--input`, `-i` | нет | Каталог YOLO для `--from-yolo`. |
| `--output`, `-o` | обязательный | Для `--to-yolo` и `--to-coco` — выходной каталог. Для `--from-yolo` — выходной CSV. |
| `--link-mode` | `auto` | Как класть изображения в выходной каталог (`--to-yolo`, `--to-coco`): `reflink` — копия без занятия места (copy-on-write); если файловая система это не поддерживает, команда один раз предупреждает `reflink недоступен (...): используется копирование` и копирует файл; `hardlink` — жёсткая ссылка; `symlink` — символическая ссылка на исходный файл; `copy` — обычная копия; `auto` — reflink, а если нельзя, копия. |
| `--image-dir` | нет | Один или несколько каталогов для поиска изображений: `--image-dir dir1 dir2`. |
| `--names-file` | нет | YAML с именами классов для `--from-yolo` без `dataset.yaml`. Формат `{0: name, ...}` или `{names: {0: name, ...}}`; список `names: [a, b]` тоже подходит. |
| `--read-all-sizes` | вкл. | Для совместимости. В обоих режимах импорта размер читается из заголовка каждого изображения. |
| `-h`, `--help` | | Показать справку. |

## Входной CSV для `--to-yolo` и `--to-coco`

Формат столбцов описан в [Формат датасета](../dataset-format.md). Для выгрузки важно:

- Нужны столбцы `image_name`, `instance_shape`, `split`, `image_width`, `image_height`. Если есть строки bbox, нужны ещё `instance_label`, `bbox_x_tl`, `bbox_y_tl`, `bbox_x_br`, `bbox_y_br`.
- Используются только строки с `instance_shape` = `box` (bbox) и `none` (кадр без аннотаций). Остальные строки, например `deleted`, отбрасываются без сообщения.
- У каждой оставшейся строки `split` должен быть `train`, `val` или `test`. `dataset.csv` из [`cveta2 fetch`](fetch.md) приходит с пустым split: назначьте его сами до выгрузки.
- `image_name` должен быть именем файла без каталогов.
- `image_width` и `image_height` — целые положительные числа.
- У bbox должны быть все четыре координаты, `bbox_x_br` больше `bbox_x_tl`, `bbox_y_br` больше `bbox_y_tl`.

Если хотя бы одна строка не подходит, команда завершается с ошибкой до записи в выходной каталог.

### Индексы классов

Индексы классов (первое число строки разметки YOLO и `category_id` в COCO; это не номер класса из реестра классов ([class registry](../../GLOSSARY.md))) строятся по меткам (label) строк bbox из всего CSV, сразу для всех split. Метки сортируются по алфавиту и нумеруются подряд: в YOLO с 0, в COCO с 1. Таблица печатается в начале работы:

```text
Классов: 3, map: {'bottle': 0, 'can': 1, 'jar': 2}
```

Индексы зависят только от списка меток в CSV. Если в другом CSV появилась или пропала метка, индексы других меток могут сдвинуться. Индексы классов двух выгрузок совпадают, только если список меток одинаковый.

### Где ищутся изображения

1. Каталоги из `--image-dir`, по порядку.
2. Каталоги всех проектов из раздела `image_cache` личной конфигурации ([personal configuration](../../GLOSSARY.md)), то есть кэш изображений ([image cache](../../GLOSSARY.md)) (см. [Изображения и кэши](../images-and-cache.md)). Запасной `cache.images_root` здесь не используется.

В каждом каталоге сначала проверяется `<каталог>/<image_name>`, затем поиск идёт по имени файла во всех подкаталогах. Из нескольких файлов с одним именем берётся путь, последний по алфавиту. Файлы внутри выходного каталога не используются как источник.

Если хотя бы одно изображение не найдено, команда завершается с ошибкой `Ошибка: не найдено 2 изображений: ...` до записи в выходной каталог. Код завершения 1. При повторном запуске прежнее содержимое выходного каталога остаётся как было.

## --to-yolo

### Что пишется

```text
output/yolo/
├── dataset.yaml
├── images/
│   ├── train/
│   │   ├── shelf_001.jpg
│   │   └── shelf_002.jpg
│   ├── val/
│   │   └── shelf_003.jpg
│   └── test/
│       └── shelf_004.jpg
└── labels/
    ├── train/
    │   ├── shelf_001.txt
    │   └── shelf_002.txt
    ├── val/
    │   └── shelf_003.txt
    └── test/
        └── shelf_004.txt
```

Создаются каталоги только тех split, которые есть в CSV. Файл разметки называется по имени изображения без расширения.

`dataset.yaml` в формате Ultralytics:

```yaml
names:
  0: bottle
  1: can
  2: jar
path: /home/user/output/yolo
test: images/test
train: images/train
val: images/val
```

`path` — абсолютный путь выходного каталога. Ключи `train`, `val`, `test` пишутся только для split, которые есть в CSV.

### Как переводятся координаты

Каждая строка bbox превращается в строку файла разметки:

```text
<индекс класса> <x центра> <y центра> <ширина> <высота>
```

Значения делятся на ширину и высоту изображения из CSV и пишутся с шестью знаками после запятой:

- x центра = (`bbox_x_tl` + `bbox_x_br`) / 2 / `image_width`;
- y центра = (`bbox_y_tl` + `bbox_y_br`) / 2 / `image_height`;
- ширина = (`bbox_x_br` − `bbox_x_tl`) / `image_width`;
- высота = (`bbox_y_br` − `bbox_y_tl`) / `image_height`.

Перед переводом bbox обрезается по границам изображения. Если после обрезки ширина или высота меньше 1 px, bbox пропускается; так же пропускается bbox меньше 1 px, который не выходил за край. Размер в пикселях сравнивается после округления до двух знаков. Это то же правило, что в `--to-coco`: обе выгрузки одного CSV содержат одни и те же bbox. Команда печатает число обрезанных и пропущенных bbox:

```text
Боксы, выходящие за границы изображения, обрезаны по ним: 1 (shelf_001.jpg)
Пропущены боксы меньше 1 px по ширине или высоте после обрезки: 1 (shelf_007.jpg)
```

Изображение, у которого есть только строки `none`, получает пустой файл разметки. Если в одном split у изображения есть и `box`, и `none`, строки `none` не влияют на результат.

Два изображения с одинаковым именем без расширения в одном split (например, `shelf_001.jpg` и `shelf_001.png`) пишут разметку в один и тот же `shelf_001.txt`.

### Повторный запуск в тот же каталог

- Изображения и файлы разметки текущего CSV перезаписываются. Если на месте изображения уже лежит тот же файл, он не трогается.
- В `images/<split>/` удаляются файлы с расширением изображения (`.jpg`, `.jpeg`, `.png`, `.bmp`, `.tiff`, `.webp`), а в `labels/<split>/` — файлы `.txt`, которых нет в текущем CSV. Так убираются изображения, удалённые из CSV или перенесённые в другой split.
- Другие файлы не трогаются. Каталоги split, которых больше нет в CSV, остаются, но становятся пустыми, и `dataset.yaml` на них больше не ссылается.
- `dataset.yaml` пишется заново.

Если `labels`, `labels/<split>` или файл разметки — символическая ссылка, команда отказывается писать (`небезопасный каталог разметки YOLO`). Каталог изображений split может быть ссылкой, только если в нём уже лежат те же файлы, которые команда положила бы туда.

## --to-coco

### Что пишется

```text
output/coco/
├── train/
│   ├── _annotations.coco.json
│   ├── shelf_001.jpg
│   └── shelf_002.jpg
├── valid/
│   ├── _annotations.coco.json
│   └── shelf_003.jpg
└── test/
    ├── _annotations.coco.json
    └── shelf_004.jpg
```

Split `val` пишется в каталог `valid`. Изображения лежат рядом с JSON своего split. Такую раскладку ожидает RF-DETR.

`_annotations.coco.json` содержит три списка:

```json
{
  "images": [{"id": 1, "file_name": "shelf_004.jpg", "width": 640, "height": 488}],
  "annotations": [
    {"id": 1, "image_id": 1, "category_id": 2, "bbox": [130.13, 51.85, 48.08, 57.24], "area": 2752.1, "iscrowd": 0}
  ],
  "categories": [{"id": 1, "name": "bottle", "supercategory": "none"}, {"id": 2, "name": "can", "supercategory": "none"}]
}
```

- `images`: все изображения split, отсортированные по имени, с номерами с 1. Размер берётся из CSV. Изображения только со строками `none` тоже здесь, без аннотаций.
- `annotations`: по одной на каждую строку bbox, которая не пропущена (см. ниже), номера подряд с 1 внутри каждого split. `bbox` = [x левого верхнего угла, y левого верхнего угла, ширина, высота] в пикселях после обрезки, округление до двух знаков. `area` = ширина × высота после обрезки.
- `categories`: все классы CSV, в каждом split одинаковые.

Перед записью bbox обрезается по границам изображения (размер берётся из CSV). Если после обрезки ширина или высота меньше 1 px, bbox пропускается; так же пропускается bbox меньше 1 px, который не выходил за край. Размер сравнивается после округления до двух знаков, то есть так, как он был бы записан в JSON. Изображение, у которого пропущены все bbox, остаётся в `images` без аннотаций. bbox, который касается границы, но не выходит за неё, обрезанным не считается. Команда печатает число обрезанных и пропущенных bbox, по одной строке на всю выгрузку:

```text
Боксы, выходящие за границы изображения, обрезаны по ним: 1 (shelf_001.jpg)
Пропущены боксы меньше 1 px по ширине или высоте после обрезки: 1 (shelf_007.jpg)
```

### Повторный запуск в тот же каталог

- Команда читает `_annotations.coco.json` прошлой выгрузки в каждом каталоге split и считает своими только перечисленные там изображения и сам JSON.
- Если в каталоге split уже лежит файл с именем изображения из текущего CSV, но прошлый JSON его не перечисляет, команда завершается с ошибкой `путь не принадлежит предыдущему экспорту COCO` и ничего не пишет.
- Свои файлы, которых нет в текущем CSV, удаляются. Каталог split, который стал пустым, удаляется.
- Чужие файлы, не перечисленные в прошлом JSON, остаются.

Выходной каталог и его родительские каталоги не могут быть символическими ссылками.

## --from-yolo

Режим выбирается по наличию `<input>/dataset.yaml`.

### Режим датасета (есть `dataset.yaml`)

Команда ожидает раскладку Ultralytics, например ту, что пишет `--to-yolo`:

```text
input/
├── dataset.yaml
├── images/
│   ├── train/shelf_001.jpg
│   └── val/shelf_003.jpg
└── labels/
    ├── train/shelf_001.txt
    └── val/shelf_003.txt
```

1. Из `dataset.yaml` берутся `names` (словарь `{индекс: имя}` или список), `path` и ключи `train`, `val`, `test`. `path` необязателен; относительный путь считается от каталога `dataset.yaml`.
2. Значение split может быть каталогом (берутся все изображения в нём и подкаталогах), файлом `.txt` со списком путей, одним изображением или списком таких значений.
3. Файл разметки изображения ищется по пути изображения, где последний каталог `images` заменён на `labels`, а расширение — на `.txt`.
4. Если файла разметки нет или в нём нет строк, изображение попадает в CSV одной строкой `instance_shape` = `none`.
5. Если изображения из списка нет на диске, команда завершается с ошибкой `Ошибка: не найдено 1 изображений из списка: ...` и не пишет CSV.
6. Изображение с нечитаемым файлом разметки пропускается с предупреждением.

`--names-file` и `--image-dir` в этом режиме не используются.

### Режим предсказаний (нет `dataset.yaml`)

1. Команда берёт все файлы `.txt` в `--input` и его подкаталогах.
2. Файл без подходящих строк (в том числе пустой) пропускается: строки `none` в этом режиме не создаются.
3. Изображение ищется по имени файла разметки без расширения: в `--input`, в `--input/images`, затем в каждом каталоге `--image-dir` и его подкаталоге `images`, затем в каталогах раздела `image_cache`. Подходят расширения `.jpg`, `.jpeg`, `.png`, `.bmp`, `.tiff`, `.webp`, `.tif` в любом регистре. Глубже одного уровня поиск не идёт.
4. Если изображение не найдено, команда завершается с ошибкой `Ошибка: не найдены изображения для 1 файлов: shelf_009` и не пишет CSV.
5. Имена классов берутся из `--names-file`. Без него и для индексов, которых там нет, метка будет `class_<индекс>`, например `class_6`.
6. `split` в результате пустой.

### Как переводятся координаты

Строка разметки — `<класс> <x центра> <y центра> <ширина> <высота>` и необязательная шестая колонка с уверенностью. Пиксельные координаты получаются умножением на размер изображения и округляются до двух знаков:

- `bbox_x_tl` = (x центра − ширина / 2) × ширина изображения, `bbox_x_br` = (x центра + ширина / 2) × ширина изображения;
- `bbox_y_tl` и `bbox_y_br` — так же по высоте.

Шестая колонка попадает в `confidence`. Если в строке больше шести чисел (сегментация, OBB, ключевые точки), используются первые пять или шесть, и команда предупреждает об этом.

Строка пропускается с предупреждением, если в ней меньше пяти чисел, есть не число, индекс класса не целый или отрицательный, центр вне [0, 1], ширина или высота вне (0, 1], уверенность вне [0, 1].

Размер берётся из заголовка каждого изображения без декодирования пикселей.

### Что пишется

Один CSV со всеми столбцами формата cveta2 (см. [Формат датасета](../dataset-format.md)). Заполнены:

| Столбец | Значение |
|---|---|
| `image_name` | имя файла изображения без каталогов |
| `image_width`, `image_height` | размер изображения |
| `instance_shape` | `box` или `none` |
| `instance_label` | имя класса или `class_<индекс>` |
| `bbox_x_tl` … `bbox_y_br` | пиксельные координаты |
| `split` | ключ split из `dataset.yaml`; в режиме предсказаний пусто |
| `confidence` | шестая колонка разметки, если она есть |
| `frame_id` | порядковый номер изображения с 0 |
| `annotation_id` | порядковый номер bbox с 1 |
| `task_id`, `task_name`, `source` | `0`, `yolo`, `yolo` |
| `occluded`, `z_order`, `rotation` | `False`, `0`, `0.0` в строках `box`; в строках `none` пусто |
| `attributes` | `{}` |

Остальные столбцы пустые. Существующий CSV перезаписывается, каталоги создаются. Если в датасете нет ни одного изображения, пишется CSV только с заголовком, код завершения 0.

## Результат

Итог печатается в конце:

```text
Готово: 8 изображений, 31 боксов, 12 классов -> output/yolo
Готово: COCO датасет сохранён в output/coco
CSV сохранён: output/predictions.csv (4 изображений, 15 строк)
```

Для `--to-yolo` число изображений — это изображения, которые положены в выходной каталог.

### Коды завершения

| Код | Когда |
|---|---|
| 0 | Выгрузка записана, в том числе с предупреждениями о пропущенных строках или файлах разметки. |
| 1 | Ошибка входных данных: нет `--dataset`/`--input`, нет split, неверный split, неверный bbox или размер, не найдено изображение, небезопасный выходной путь, нет `.txt` в режиме предсказаний, не читается конфигурация. |
| 2 | Неверные аргументы командной строки: не указано направление, указано два направления, нет `--output`. |

## Интерактивный и неинтерактивный режим

Команда ничего не спрашивает и одинаково работает с `CVETA2_NO_INTERACTIVE=true` и без него. Она не подключается к CVAT, но читает конфигурацию ради раздела `image_cache` (см. [Конфигурация](../configuration.md)).

## Частые ошибки

**`Ошибка: у 8 изображений не задан split. Примеры: shelf_001.jpg, ...`**

В CSV пустой split. Назначьте `train`, `val` или `test` каждому изображению.

**`Ошибка: недопустимый split ['holdout']: shelf_001.jpg. Допустимы train, val, test.`**

Другие значения split не поддерживаются.

**`Ошибка: для --to-yolo / --to-coco укажите --dataset / -d.`** и **`Ошибка: для --from-yolo укажите --input / -i.`**

Не указан вход для выбранного направления.

**`cveta2 convert: error: argument --to-coco: not allowed with argument --to-yolo`**

Указано два направления. Запускайте команду отдельно для каждого.

**`Ошибка: некорректный bbox 'shelf_001.jpg' в output/dataset.csv`**

Нет координаты, координата не число, или правый нижний угол не правее и не ниже левого верхнего.

**`Ошибка: некорректное имя изображения в output/dataset.csv: 'shelf/001.jpg'`**

В `image_name` есть каталог. Выгрузка принимает только имя файла.

**`Ошибка: не найдено 2 изображений: shelf_001.jpg, shelf_002.jpg. Выгрузка не начата.`**

`--to-yolo` или `--to-coco` не нашла изображения из CSV ни в `--image-dir`, ни в кэше изображений. Выходной каталог не изменён. Укажите правильный `--image-dir` или скачайте изображения ([`cveta2 s3-sync`](s3-sync.md)).

**`Ошибка: не найдено 1 изображений из списка: /home/user/input/images/train/shelf_001.jpg. CSV не записан.`**

`--from-yolo` в режиме датасета: файл-список split называет изображение, которого нет на диске. Верните файл или уберите строку из списка.

**`Ошибка: не найдены изображения для 1 файлов: shelf_009. CSV не записан.`**

`--from-yolo` в режиме предсказаний: для файла разметки нет изображения с тем же именем. Укажите каталог с изображениями в `--image-dir`.

**`Ошибка: путь не принадлежит предыдущему экспорту COCO: output/coco/test/shelf_004.jpg`**

В каталоге COCO лежит посторонний файл с именем изображения из CSV. Уберите его или выберите другой `--output`.

**`Ошибка: не найдено .txt файлов в output/predictions`**

В режиме предсказаний в `--input` нет файлов разметки, или неверный путь.

**`Invalid shared project configuration ...`**

Команда читает конфигурацию, хотя к CVAT не подключается, и общая конфигурация ([global configuration](../../GLOSSARY.md)) не прошла проверку. Ошибка возникает и тогда, когда в общей конфигурации пустой `cvat.host`. Код завершения 1. Исправьте конфигурацию (см. [Конфигурация](../configuration.md)).

## Из Python

```python
cveta2.convert_to_yolo(dataset, output_dir, *, image_dirs=None, link_mode="auto") -> pathlib.Path
cveta2.convert_to_coco(dataset, output_dir, *, image_dirs=None, link_mode="auto") -> pathlib.Path
cveta2.convert_from_yolo(input_dir, output_csv, *, names_file=None, read_all_sizes=True, image_dirs=None) -> pathlib.Path
```

Параметры совпадают с флагами команды. `convert_to_yolo` и `convert_to_coco` возвращают выходной каталог, `convert_from_yolo` — путь к CSV. При ошибке входных данных поднимается `cveta2.Cveta2Error`. Подключение к CVAT не нужно.

```python
import cveta2

out = cveta2.convert_to_yolo(
    "data/merged.csv",
    "output/yolo",
    image_dirs=["data/images"],
    link_mode="hardlink",
)
print(out / "dataset.yaml")
```

Общие сведения о Python API — на странице [Python API](../python-api.md).
