# SIP-329 image download regression, 2026-11-28

The image downloader in cveta2 0.16.2 (checkout `8bf1e29`) can substitute an unrelated image from the project's own S3 folder. A CVAT frame named `hk-with-mem/a.jpg` points the downloader at `hk/hk-with-mem/a.jpg`. When that object is absent, the downloader falls back to the basename and accepts `hk/a.jpg`. Both annotations then appear to have downloaded successfully. The bucket listing itself already uses the folder boundary `hk/`.

Run the product regression from the repository root with the project's test dependencies installed.

```sh
python -m pytest -n0 tests/test_image_download_failures.py::test_sibling_prefix_frame_cannot_claim_another_image_by_basename
```

With the regression test applied to the original checkout, the downloader reported two downloads and zero failures. With the fix, it reports one download and one failure, identifies the suspect CVAT frame, and retains the valid nested object `hk/hk-with-mem/b.jpg`.

The repository's live integration server reported CVAT 2.82.0 from `/api/server/about`. The regression supplies frame metadata and S3 objects locally and requires no CVAT server. The command and server version from the original deployment are unknown. The regression establishes the client-side substitution independently of how the original task acquired its frame names.
